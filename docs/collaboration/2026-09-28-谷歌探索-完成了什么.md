## 一句话

Google Discover 是手机 Google 应用首页上的推荐信息流，用户不用搜索就会刷到文章。它挑内容主要看五点：大图、机器能读懂的文章信息、作者是不是真人、内容新不新、手机上看着舒不舒服。截图里所有能靠改网站做到的条目，现在都已经做完，而且每一条都有自动测试守着，以后有人误删测试会报红。

## 做了什么，为什么要做

| 截图里的要求 | 网站现在的状态 | 为什么重要 |
|---|---|---|
| 大图：宽 ≥1200px、16:9、≤500KB | 82 篇文章每篇都有一张 1200×675 的分享图，最大的也不到 500KB。用的是文章自己的真实头图，没有生成产品图 | Discover 卡片没有大图就只能显示小缩略图，点开率差很多 |
| `max-image-preview:large` | 所有页面、所有搜索引擎都加了 | 这是允许 Google 用大图显示我们页面的授权，不加就只能用小图 |
| RSS | 英文 `/feed.xml`、西语 `/es/feed.xml`、葡语 `/pt/feed.xml`，每个 82 条，按时间倒序，带作者和大图 | Google 靠它尽快发现新文章；西语和葡语读者在 Discover 里看到的是自己语言的版本 |
| 结构化数据 Article / NewsArticle | 技术指南标成 TechArticle，公司新闻标成 NewsArticle，都写了作者、发布方、发布日期和**最后修改日期** | 让 Google 准确知道这是什么文章、谁写的、什么时候更新过 |
| 明确的作者信息（E-E-A-T） | **新做了作者页 `/company/johnson-liu/`，十种语言都有**：职位、学历、LinkedIn、他写的全部文章。每篇文章的署名、结构化数据和社交分享标签都指向这个页面 | 「作者是不是真人、是不是这个领域的」是 Google 判断可信度的核心问题。只链到 LinkedIn 就是把可信度交给了别的网站 |
| 内容新鲜度 | **新做了修改日期自动更新**：文章正文真改过，日期才会变 | 以前「最后修改日期」永远等于发布日期，Google 以为我们从来不更新 |
| 手机体验、没有干扰弹窗 | 手机上看文章不再弹促销卡片；面包屑、联系页已按手机优化 | Discover 的流量九成来自手机，弹窗会被当成干扰性体验 |

## 两个新机制，以后写文章要知道

### 1. 修改日期是自动盖的，不要手填

以后改文章，改完跑一次：

```
npm run content
```

它会对比每篇文章正文（标题、摘要、正文、常见问题，英西葡三种语言）有没有真的变化。变了，就在这篇文章上写入今天的日期 `updatedAt`；没变，什么都不动。

有三点要注意：

- **只改 SEO 标题或描述不算更新**，日期不会动。改个标题就说「文章更新了」，Google 会把这当成刷新鲜度的作弊。
- **忘了跑也没关系**，`npm run check` 会拦下来，并提示「run: npm run content」。
- 更新日期会同时出现在四个地方：文章页上的「Updated」一行、结构化数据的 dateModified、社交分享标签，还有站点地图的 lastmod。

### 2. 作者页的资料只从文章里读

作者页上的名字、职位和学历，都是直接从文章 JSON 的 `author` 字段读出来的，没有另存一份，所以署名、结构化数据和作者页不可能对不上。作者页上没有编写任何简介，只放文章里已经有的信息。

以后要加第二位作者，在 `src/data/authors.ts` 里加一行名字，然后按 `company/johnson-liu` 的样子加路由就可以了。

## Spooner 上线后要做的事

1. johns 那台机器跑完 `npm run release:hyde` 之后，记得 purge Cloudflare。
2. 在 Search Console 的「站点地图」里提交 `/es/feed.xml` 和 `/pt/feed.xml`（英文的 `/feed.xml` 之前已经在 robots.txt 里）。
3. 拿任意一篇文章的网址去 Google「富媒体搜索结果测试」检查一遍：作者那一项应该显示 Johnson Liu，并带着站内作者页的链接。
4. 过两到四周，去 Search Console 看有没有出现「Discover」报告。只有网站拿到过 Discover 展示，这个报告才会出现。

- **作者页加照片**：必须是 Johnson 本人的真实照片，由你提供。
