## 判断标准：只有三种工具值得装

这个项目已经证明过，工具多不等于做得好。`SKILLS.md` 里算过一笔账：
十个仓库一共 1,586 个 skill，全装约 11 万 token，每次会话开头就吃掉，
而且选项一多，选择本身会变差。

所以每一条只问三个问题：

1. **它解决的是我们真的有的问题吗？** 不是「听起来有用」。
2. **它要不要密钥、登录、部署或新运行时？** 要，就是一次独立决策，
   不能顺手装。
3. **它会不会和已有的纪律打架？** `AGENTS.md` 已经规定了提交、
   验证、图片、purge 的流程；一个带自己那套工作流的框架装进来只会分裂纪律。

## 二、已装的 skill（`.agents/skills/`，四个仓库 73 个）

`SKILLS.md` 有完整清单和更新方式。按对这个站的实际用处排：

| Skill 组 | 什么时候自动启用 | 对我们的价值 |
|---|---|---|
| **impeccable**（前端设计审查，61 条确定性检测） | 改过网页 UI 之后的收尾 | ✅ **高**。它不调 API 就能查出「一看就是 AI 做的」模式：默认字体、紫色渐变、卡片套卡片。和甲方那句「不要花里胡哨」是同一件事的机器版 |
| **geo-seo**（13 个子 skill，`/geo audit <url>`） | 做 GEO 审计之前 | ✅ **高**。但要注意别重复造轮子 —— 我们自己的 `npm run seo:deadlinks` 和 `scripts/lib/seo-audit.mjs` 已经覆盖死链、hreflang、canonical、JSON-LD |
| **marketingskills**（CRO / 文案 / 分析） | 改转化路径、批量产品文案之前 | ✅ **中**。`copywriting` 在写 35 篇文章时用过 |
| **ui-ux-pro-max**（79 种风格、192 条行业推理规则） | 页面重设计 | ⚠ **低**。我们不缺风格选项，我们缺的是克制。FSB 那套已经定了 |
| **taste-skill**（反 slop，三个可调参数） | 同上 | ⚠ **低**，和 impeccable 重叠 |

**要改的一条纪律：** `AGENTS.md` 已经写了「每个代理开工前自动查看当次会话
暴露的 skills」。这条今天执行得不够 —— 改了页眉页脚（网页 UI）之后
没有跑 impeccable 的 detector。下次改 UI 收尾要跑。

## 四、真正值得花钱的三样（要甲方决定，不是我们偷偷装）

按对**被引用**这个目标的直接程度排：

### 1. Search Console 的 URL 导出（免费，只要甲方点几下）

这不是工具，是数据。今天写 `2026-09-17-gsc-index-coverage.md` 时，
十条里有两条（404 那 49 个、5xx 那 1 个）**我无法在不看 URL 的情况下修**。
这是当前投入产出比最高的一项，成本是甲方两分钟。

### 2. Bing Webmaster Tools 的 IndexNow（免费，已在用）

我们已经在提交。值得确认的是提交是否覆盖了新的 645 个葡语页面和
新的葡语新闻路由 —— 这条我会在下次构建后自己核。

### 3. DataForSEO（付费，要甲方拍板）

`every-app/open-seo` 那套的底层数据源。它能回答我们现在回答不了的问题：
我们的 50 个北美长尾词，各自的搜索量和竞争度到底是多少；我们为哪些词
排在第 11–20 名（差一点就上首页的那些）。

**但是**：这个站现在的瓶颈不是「不知道该写什么词」——
关键词报告里已经有真人打进来的问题，今天全部写进问答块了。
瓶颈是**内容的量和被链接的结构**。在葡语正文 35 篇写完之前，
买这个数据不会改变任何决定。

**建议：先不买。** 等葡语写完、问答块的引用数据出来（两到三周），
再看还缺不缺。

## 五、一句总结

**今天没有一个工具缺口挡住了任何工作。** 挡住工作的是三件事，
都不是工具能解决的：

1. 工厂还欠六个订单码、五个尺寸、308-S/308-D 的端盒问题。
2. 68 个型号没有照片，所以它们必须 noindex。
3. 35 篇文章的葡语正文要人写（今天写完 10 篇）。

工具清单上任何一项都不解决这三条中的任何一条。
