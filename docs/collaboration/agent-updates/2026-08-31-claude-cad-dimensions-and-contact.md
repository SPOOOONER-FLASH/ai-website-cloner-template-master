# Claude — CAD 图纸里的尺寸；五个把手共用一个错误尺寸；站上没有任何邮箱

## 一、甲方是对的：规格和图纸对不上，而且是系统性的

**五个玻璃门拉手（100 / 102 / 104 / 106 / 107）全都写着 `Size = 32x300x600 mm`。**
这是 stahlock 一条商品文案被复制到整个系列。我把五张图纸逐张打开读了：

| 型号 | 总长 | 中心距 | 管径 | 其他 |
|---|---|---|---|---|
| 100 | 600mm | **148mm** | 32mm | 支距 26mm · 固定中心 30mm · 玻璃间隙 7.5mm |
| 102 | 600mm | **147mm** | 32mm | 8mm |
| 104 | 600mm | **头 149mm / 尾 133mm（锥形）** | 32→19mm | 固定中心 34mm |
| 106 | 600mm | **125mm** | 32→18.5mm | 握持段 140mm · 7mm |
| 107 | 600mm | **148mm** | 32mm | 8mm |

**五张图纸里没有一张出现 300mm。** 五个型号的中心距各不相同（148/147/149-133/125/148），
正是这种"差一点"的差异说明跨型号复制尺寸是危险的。已删掉那条 `Size`，
换成每个型号自己图纸上的数字。

另外补了 `19-130MM`（原本只有 1 行规格）与 `9014` 不锈钢执手 —— 后者正是那 32 个
"无数据可差异化"的拉手之一，**图纸就是那份缺失的数据**：135mm 执手长、60mm 出挑、
53mm 座径、19mm 断面、8mm 方轴。

共 **7 个产品 · +43 行 · −5 行**（被图纸推翻的）。

## 二、找图纸这件事，我走了两条弯路，记下来省得重走

1. **按"纯黑墨水"筛** → 漏掉每一张细线图纸。图纸的线是抗锯齿的灰，不是纯黑。
2. **按"长直线"筛** → 把深色照片全捞进来了（每一行都有长暗色游程）。

最后能用的判据是**纸的特征而非线的特征**：图纸几乎没有中间灰（没有明暗过渡），
而不锈钢照片无论背景多白，主体都是大片中间灰。`white>0.85 && mid<0.13` 召回住了
1478 张里的 248 张。**但精度仍然不够** —— 白底摄影棚照片照样通过，而且同一张营销拼图
被逐产品重新编码后哈希还不一样，去重也救不了。

**剩下的活**：`tmp/claude-cad/worklist.json` 里 A 组 40 个（≤3 行规格）、B 组 92 个
（有尺寸行待核对）。我读了其中 8 张。**这一步没有便宜的自动化，得人眼或 OCR 过一遍**，
我不假装它能自动跑完。

## 三、站上没有任何一个邮箱地址

`site-settings.json` 的 `contact.email` 是空的，全站 grep 不到一个 `@`。
所有询盘路径要么是表单，要么跳去阿里巴巴。两个后果：

- 想用自己邮箱写信的买家无处可去
- **AI 被问到「怎么联系 Canton Hyland」时无话可引** —— Organization JSON-LD 里没有 contactPoint

已把机制建好，**值留空**，甲方在 CMS 填上就自动出现在三处：

| 位置 | 用哪个地址 | 理由 |
|---|---|---|
| Organization JSON-LD `contactPoint` | sales + technical 两条 | LLM 唯一能引用的结构化联系方式 |
| 页脚，紧挨阿里巴巴链接下方 | sales | 不想走阿里的买家的出口 |
| **产品页，"Request a quote" 正下方** | technical（无则 sales） | 意向最强的一刻，且 subject 自动带型号 |

产品页那条 mailto 会自动填 `subject=<型号> — <名称>`，回信时不用问"您说的是哪一款"。

**等甲方定**：`lock@` / `tec@` / `hyde@` 分别放哪个位置。我的建议是
sales=`lock@cantonlock.com`、technical=`tec@cantonlock.com`，`hyde@` 留给公司页。
