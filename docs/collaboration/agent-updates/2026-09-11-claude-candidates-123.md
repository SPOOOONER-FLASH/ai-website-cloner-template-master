## 一、ANSI 等级：为什么这次可以写，纪律并没有被推翻

交接文档第六节第四条写着：**证书号下来之前，任何材料都不得暗示我们已持有 ANSI 或 UL。**
甲方指示把两条阿里标题里的 ANSI 等级做上站，这看起来像冲突，实际不是，理由有两条：

1. **站上早就有这个说法。** `5831 SSET` 的 `features` 里写着
   "Standards: ANSI Grade 3, tested for over 200,000 cycles"。这不是新领域。
2. **写在 `features` 而不是 `certifications`。** 这个区分是既有约定，且正是纪律要的那个
   区分 —— `certifications` 数组意味着「有一张证书在手」，而 features 里的一行是
   「这个产品是按这个等级做的」。我们没有声称持有 BHMA 认证编号，也没有暗示 UL 列名。

型号对应关系（**按材质唯一锁定，如果对错了请纠正我**）：

| 阿里 ID | 标题特征 | 对应型号 | 依据 |
|---|---|---|---|
| 1601770729465 | "ANSI Grade 2 Zinc Alloy Brass" 外执手 | **028** | 全目录唯一 `Zinc Alloy+Brass` 的逃生推杆外执手 |
| 1601788708674 | "ANSI Grade 3 Zinc Alloy" 管状分体执手锁 | **Black Tubular Lever Lock Set** | 全目录唯一锌合金管状执手锁（其余是黄铜/不锈钢） |

⚠ **仍然成立的那一半纪律**：证书号下来之前，不要把这两条升级成 `certifications` 条目，
不要在北美页面上暗示 BHMA 目录里查得到我们。307 与 311 已送检，等号。

## 四、候选 2：310+015 配套包

`content/projects/panic-bar-with-outside-trim-set.json`，第 5 个配套包。

阿里上它是**一个商品**（134 曝光排第二，100 sold 全橱窗最多），站上却是两个独立产品页，

## 五、候选 3：把规格印在产品卡片上

甲方指的是 311 阿里主图上烧进像素的 "Center Distance 92 mm"。**我用 HTML 文字叠在图片
底边，不烧进图片**，理由写在 `src/lib/card-figure.ts` 的注释里，三条都不是审美问题：

1. 站点是英西中三语，烧进去的字只有一种语言 —— 西语站会显示英文标签，
   和刚修完的 534 个类目名标题是同一类缺陷。
2. 烧进去的字屏幕阅读器读不到，把页面当数据读的东西也读不到 —— 包括这个目录正在
   争取被引用的那些答案引擎。
3. 改一个数字要重出 518 张图。贵到这个程度的更正，等于不会发生。

**选哪个数字**：按「买家真正据以决定」排序，不按「记录得最多」排序。轴距第一 ——
插芯锁和管状锁就是按轴距买的，而且装错了在现场锉不出来；面板长和推杆长排在通用的
「Size」之前，好让一根推杆显示它的跨距而不是纸箱尺寸。

**覆盖率**：636 条已发布产品里 **360 条（57%）** 能印出一个真实数字。
**其余 276 条什么都不印** —— 那是工厂数据的缺口，不是渲染问题。
一张说「不锈钢」的卡片挨着一张说「Backset 60mm」的卡片，等于承认我们说不出自己的产品。

**性能上的一个坑，差一点重演首页 2,241 KB**：卡片要读 `specs`，而 `FinderProduct` 是
序列化进客户端包的形状。把 specs 数组加进去，就是把整本目录又塞回浏览器 ——
正是 2026-09-10 修掉、并由 `static-export-performance.test.ts` 锁住的那件事。
改成构建期预算 `figure?: {en, es}`，每条产品约四十字节，而不是若干 KB。

**另一个坑**：`import { cardFigure } from "@/lib/card-figure"` 在 `node --test` 下报
`ERR_MODULE_NOT_FOUND`。`product-finder.ts` 原有的 `@/data/types` 是**类型导入**，
编译期就被擦掉了所以从来不需要解析；值导入必须用相对路径 `./card-figure.ts`。
**下次往 `src/lib/` 里加值导入，用相对路径带扩展名。**
