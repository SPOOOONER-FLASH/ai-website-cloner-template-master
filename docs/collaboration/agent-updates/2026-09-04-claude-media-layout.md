# 2026-09-04 · Claude · 配置器的收敛可视化，产品页图片视频重排

用 `impeccable` 的 `layout` 参照做的：先量、再定空间论点、再改、最后复量。
每一条结论下面都有渲染出来的数字，不是"看着更好"。

## 一、配置器：预览panel 现在显示的是**候选集在收缩**

### 原来是什么

`left.find(p => p.heroImage?.src)` —— 剩余产品里的第一个。两个问题：

1. **它是任意的。** 读者没有选过它，也无从知道为什么屏幕上是它。
2. **它把这个工具唯一在做的事藏起来了。** 从 435 个收窄到 6 个是全部价值所在，
   而一个不变的方块什么都没传达。

### 现在是什么

**候选产品本身**，随着收窄一块一块地少：9 → 6 → 2 → 1。
最后剩一个时占满整个 panel，**有演示片就播它**。

列数跟着数量降 —— 这是关键：同样的宽度分给更少的方块，
**收窄被感受为剩下的产品变大**，而不是一个数字变小。

| 候选数 | 列数 | 桌面单块宽度 |
|---|---|---|
| 5–9 | 3 | 142px |
| 3–4 | 2 | — |
| 1–2 | 1 | 满宽 |

### 为什么这里**不**照抄 FSB

他们的预览用 Cloudinary 图层合成**一个想象出来的产品**，因为他们的配置器是
按单定制一把执手。我们是从 435 个**已经存在、已经拍过照**的东西里选，
所以诚实且更有用的画面是那份候选名单在变短。

**这也是他们做不到的事。**

## 二、产品页：演示片从"买按钮后面"挪出来

### 量出来的问题

`/products/panic-exit-devices/015-panic-exit-device/`，1440×950：

| | 位置 |
|---|---|
| 主图 | y=612，673×673 |
| **演示片** | **y=1349** —— 主图下方 737px，**在两个购买按钮下面** |
| 图库 | y=1817 |

买家必须滚过「索取报价」的按钮块，才会发现**存在一段这个零件在工作的影片**。

**这对这位读者是错的顺序。** 一个规格师的问题依次是：这是什么 →
**它能不能满足我的需要** → 装得下吗 → 怎么订。照片答第一个，规格表答第三个，
按钮答第四个 —— 而全页唯一回答第二个的，是三十秒里一只戴手套的手压下推杆。
**把购买请求放在证据前面，是在要一个还没给依据的决定。**

### 改了什么，以及为什么这还不够

演示片移进主图那一栏、紧接照片下方，并且**占满栏宽** ——
旧的是 `md:grid-cols-2`，而 35 个有片子的产品里 34 个只有一段，
所以每一个都在画半宽的视频加半边空白。

**然后我复量了：y 从 1349 只走到 1301。** 只挪了 48px。

原因是**主图自己就已经越过首屏了** —— 上方页面结构占 612px，主图 673px 见方，
所以任何在满栏方块下面的东西都必须滚动才够得着，**在它下面怎么重排都改变不了这件事**。

### 所以真正的修法是把信号放到眼睛已经在的地方

摘要下面加一行 **「Watch it work · 0:35」**，在文字栏里，**y=680，首屏之内**。
锚点跳到视频。时长写出来，读者按之前就知道自己要花多久。

用 `<a href="#…">` 而不是滚动脚本：水合之前就能用、可以新标签页打开、
`scroll-margin-top` 处理吸顶导航。屏幕阅读器上两个 span 会连读成
"Watch it work0:35"，所以补了 `aria-label`。

## 三、图库：现在有"第一张"

原来是 `grid-cols-2 md:grid-cols-3 xl:grid-cols-4` —— 七张同一把锁的照片全部等大，
**没有任何阅读顺序**，眼睛必须逐张检查才知道哪张值得看。

甲方自己的文件名带着他们的顺序（`2-015.jpg`、`3-015.jpg`…），导入时保留了。
所以第一张图库图就是他们选来放在最前的那一张 —— 给它两列两行，
让那个选择变得可见，形成**一大 + 一串小**的节奏。

复量：lead 673×673，其余 328×328。手机上两列，lead 跨两列（343×343），
其余 164×164 —— 同一个关系，不是另一套。

## 四、顺带修掉的两个缺陷

1. **「1 products」。** 计数那行是把 `narrowing(n)` 生成的句子砍掉数字前缀，
   于是剩一个时显示 "products"，而那个大号动画数字走到 1 恰恰是整件事的高潮。
   改成直接取单位。

2. **空状态在说谎。** 候选为 0 时显示的是「这个型号的照片正在准备中」——
   那句话在"有候选但都还没照片"时是真的，在"什么都不匹配"时是假的。
   而后者正是**一条过期的分享链接**会落到的状态：配置是拿来贴进邮件的，
   而产品可能在发出和打开之间被下架。告诉那位读者我们在准备照片，
   是让他去等一个永远不会到的东西。

   收窄模型保证「任何**选择**都不会通向零」，这是它覆盖不到的那个情况：
   一条在别处拼出来的 URL。

## 五、改了一条测试，说明为什么

`product-image-zoom.test.ts` 断言的是图库那一行 JSX 的**完整字面量**，包含 `key`。
把每张图包进网格单元 —— key 移到外层、缩放行为一个字没动 —— 让一条以
"hero 和 gallery 用同一个缩放层"命名的测试失败了。

改成断言**不变量**（两处都经由 `ProductImageZoom` 且带同样的 locale），
不是源码字符串。**一条会被版式改动碰倒的测试，最后会被人改成通过而不是被读。**
