## 一个存在了很久、今天才看得见的缺陷

西语文章的正文早就翻好了。**问答块从上线那天起就是英文的。**

没人发现，因为发现它需要读西语页面。它变得可见，是因为葡语正文今天翻完之后，
同一个错配在另一棵树上又出现了一次 —— 葡语标题下面挂着英文问题。

这是这个仓库里找到 bug 的常规方式：**一个 bug 的第二个实例，才让第一个从
「疏漏」变成「模式」。**

## 做了什么

35 篇 × 4 组 × 3 语言 = **405 组问答**，全部有译文。

| | 之前 | 现在 |
|---|---|---|
| faq.en | 35/35 | 35/35 |
| faq.es | **0/35** | 35/35（135 组） |
| faq.pt | **0/35** | 35/35（135 组） |

`src/lib/article-faq.test.ts` 的第一条测试是**逐语言**检查的：葡语答案里的数字
必须出现在葡语正文里。这比听起来严格，而且正是要点 —— 翻译不能悄悄引入一个
数字，也意味着这些译文是**对着正文翻的，不是对着英文答案翻的**。

问题是按「有人会打出来的问题」翻的，不是按英文字面翻的。
「how do you ensure that double doors close in the right order」是 Bing 关键词
导出里的英文原句；葡语和西语的对应版本是巴西规格师和拉美规格师会打进去的句子，
更短，用的是各自行业自己的词。

术语跟着已有正文走：西语 selector de cierre / manija / picaporte / pestillo /
rosetón；葡语 barra antipânico / mola aérea / maçaneta / ferragem。
尺寸、型号、标准编号一律不译。

## 审计里加了这一条

`npm run audit:pt` 之前**看不到**问答块 —— 它们在 `faq.<locale>` 下面，
不是带 `…Pt` 后缀的字段，`countRecords` 够不着。没有任何东西在量它，
所以没人知道。

现在：

```
  article Q&A       35    ES 100%   PT 100%   (135 ES pairs, 135 PT pairs)
```

只有**组数与英文相同**才算完成。部分翻译在这里不算部分覆盖，
而是一个页面在一种语言里回答的问题比另一种少 —— 那是内容差异，不是翻译缺口。
