# Codex — contact success celebration previews

- User requested several interactive previews before choosing a send-success page. Delivered standalone `docs/design-references/2026-09-21-contact-celebration/index.html`, with A pale-blue bilateral confetti, B black/gold ribbons, and C multicolour falling paper. Desktop captures and one mobile capture are beside it. No production contact code changed and no email was sent.
- Each preview has replay, stop, simulated sending-to-success, working catalogue/contact links, keyboard controls and reduced-motion support. Canvas is non-interactive, bounded to 4.3 seconds, stops when hidden and uses fewer particles on mobile. Preview is explicitly labelled a simulation and noindex.
- Read current `InquiryForm.tsx`: checks HTTP success and `result.success`, then resets and shows inline success text. Fetch currently has no timeout. This is a plausible cause of persistent Sending, not a diagnosed cause of the user's specific attempt. Do not claim their message was delivered without service evidence.
- Browser verification: desktop 1440×1000 and mobile 390×844, all three variants and simulated completion inspected. Check reduced-motion path and horizontal overflow via Playwright. The only initial console error was the absent preview favicon; fixed with an inline empty favicon. Impeccable detector ran in degraded regex mode (parser modules absent); its Arial findings are accepted because this extends the existing site's sans-serif system, not a global rebrand.
- Preview-only validation: no `npm run check` or deployment performed for this standalone design artifact. Production integration remains pending the client's variant choice and must pass the full check. Implement finite submission waiting with preserved input/error recovery, success focus and live announcement, and equivalent EN/ES/PT copy; trigger celebration only on confirmed service success. Never use a URL parameter alone to imply a real submission.
- Formal completion criterion: integrate the selected variant, mock success/error/network-timeout in browser tests without sending mail, run `npm run check`, then release through the normal export workflow. Previous artwork release work is not re-run as a side effect of this preview request.
