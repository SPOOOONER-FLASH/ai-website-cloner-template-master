## 题库怎么写的

**人设不是消费者。** 网上流传的版本用「刚搬进纽约小公寓的 25 岁女生买桌面收纳盒」。
我们的买家是五金进口商或在做门表的项目采购：他问 backset、handing、防火等级、
MOQ、欧标锁芯、交期，并且会拿我们和 Assa Abloy、Dorma、Kale 以及更便宜的广东厂比。
题目按他的语域写 —— 该口语的地方口语，该技术的地方技术。

20 个**通用问题**（每个类目都会被问）+ 15 个类目 × 10 个**类目专属问题** = 170。
通用题对每个类目都成立，所以每个类目实际覆盖 30 个问题。

每个问题都标了「什么东西能回答它」，所以覆盖率是**量出来的不是猜的**：

| `needs` | 判定方式 |
|---|---|
| `spec` | 该类目产品里带这个规格标签的比例。≥90% 记完整，>0 记部分，0 记无 |
| `faq` | `content/faq.json` 里有这条**且答案非空**。空答案不算回答 |
| `gap` | 站上今天没有任何东西回答它。**这些就是交付物** |

## 三个值得立刻看的数字

### 1. 「部分」58 条，比干净的空白更糟

数据在一部分记录上有、另一部分没有。对答案引擎来说，这看起来是可引用的来源，
**直到引到缺的那条为止**。例：

```
Finish        285/435    「有哪些表面处理」在 150 个产品页上答不了
Application   213/435    「用在什么门上」一半答不了
Cycle life    102/435    「循环寿命多少」四分之三答不了
```

这与图纸提尺寸、甲方补 finish/用途 是同一批工作，不是新任务。

### 2. 通用题里最贵的 5 条全是空 FAQ，且全被甲方卡住

MOQ、交期、样品、付款方式、OEM —— 五条都是 `content/faq.json` 里**有问题、答案为空**。
按内容纪律我没有编。这是**单项价值最高的内容缺口**：买家问价之前先问这五个，
答案引擎也拿它们当采购意图的判据。

甲方那边这五个答案在阿里后台就能导出（HANDOFF 七节已记）。

**「Do you export worldwide?」我补了** —— 它不需要甲方新数据，
`src/data/home.ts` 已发布的文案里就写着「more than thirty export markets」，
把已公开的事实写进 FAQ 不算编造。29 个完整答案里新增的就是这一条。

## 反复出现的四个横向缺口（一次写作能填掉 20+ 个问题）

这些不需要甲方给新数据，只需要写：

1. **盒内配件**（Box contents）—— 螺丝、方轴、锁扣板、垫片含不含？
   出现在 hinges / handles / closers / glass / grip sets，是最常见的错单原因。
2. **销售单位** —— 铰链按只还是按对卖？报价差一倍。
3. **耐腐蚀说明** —— 不锈钢等级、盐雾、湿热。出现在 stainless / hinges / bathroom。
4. **成套/搭配** —— 「玻璃门一樘需要哪几件」「把手配哪个锁体」。我们同时卖这些件，
   却没有一处把它们连起来。

另有两个**边界声明**类缺口：HS 编码（每个进口商都要）、保修（问完价格就问这个）。

## 怎么用

```bash
node scripts/audit-question-coverage.mjs            # 汇总
node scripts/audit-question-coverage.mjs --gaps     # 只看没答的
node scripts/audit-question-coverage.mjs --markdown # 重新生成报告文件
```

补了规格或填了 FAQ 之后重跑，数字自己会动。**不要为了让数字好看去编答案** ——
空是诚实的，编造是事故，采购商照着下单。
