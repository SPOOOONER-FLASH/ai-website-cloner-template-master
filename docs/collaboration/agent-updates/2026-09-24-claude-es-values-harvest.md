## 补上 `Center distances`，并改正两条我自己写错的

`Center distances` 的西语取 **「Doble distancia entre ejes」**，不是字面的复数。311 的
`specsEs` 里早就是这么写的——一个锁体上两个葫芦孔位（72 / 92），审校当时写的是意思而不是
字面复数。按记录里的写法建键，重跑才会重现页面上已有的文本而不是把它改掉。
2026-09-11 那次事故被脚本注释引用的例子，正是这一行。

**改正两处我上一次凭空译的词条**，它们与页面上已有的西语不一致：

| 键 | 我上次写的 | 改为（与 072 页面一致） |
|---|---|---|
| `Used with` | Se utiliza con | **Se usa con** |
| `Follower` | （故意不加） | **Seguidor** |

`Follower` 那条我上次的判断是错的。我以为不加键就等于「把问题挂着」，其实不加键只会让
重跑把页面上已有的 `Seguidor` 那一行退回英文。**页面用什么西语，和英文行本身对不对，
是两件事。** 英文那行仍然可疑——值是 `9 × 9 × 130mm`，9mm 方杆长 130mm，那是方轴
（表里已有 `Cuadradillo`），不是 follower 指的凸轮——但那是要问工厂的**记录**问题，
等答复后在记录里定向修，不是靠术语表缺一个键来表达。

## 追平：39 个规格值，74 行

AGENTS.md 把这件事单列为一个任务，并说它是全量重跑重新变安全的前提：
「`SPEC_LABELS_ES` / `SPEC_VALUES_ES` 必须先追平 `specsEs` 里已经存在的内容」。

量了一下（用 `--only` 圈到 590 条 HYDE 记录跑只读报告，避开 translator 在雷茵记录上抛错）：

| | 追平前 | 追平后 |
|---|---|---|
| 未映射词条 | 39 | **0** |
| 受影响行 | 75 | 0 |
| 其中现有西语、重跑会丢 | **74** | **0** |

这 39 条**全部从记录里收割**，不是重新翻译。收割时检查过同一英文值在全目录是否有两种西语
写法——**0 冲突**，每个英文值在全目录只对应一个西语字符串。只有 `6068 Mortise Lock Series`
全目录都没有西语，是唯一新译的一条。

## 但全量重跑**仍然不安全**，原因换了一个

追平之后我真跑了一次全量 `--write` 验证幂等，结果不是零改动：

| 仍会被改写的 | 条数 |
|---|---|
| `summaryEs` 被摘要组装器打回残句 | **240** |
| `nameEs` | 2 |
| 规格行的数字格式漂移（`1050mm` → `1050 mm` 一类，不是退回英文） | 304 行 |

样本：`001` 的 `summaryEs` 会从
「Guarnición exterior con manija para barra antipánico, de acero inoxidable 304, para puerta cortafuego.」
变成「Una barra antipánico, para puerta cortafuego.」

这正是文案会话今天手工重写的那 18 条的同一个毛病，只是全目录有 240 条会被打回。
已全部还原，**一条记录都没留下**。

**结论：规格值这一路的退回风险清掉了，摘要组装器这一路还在。`--only` 仍然是必须的，
不要跑全量 `--write`。** 摘要组装器是另一个任务（组装器在规格行少时只能吐残句），
归文案会话的 `summary*` 车道。
