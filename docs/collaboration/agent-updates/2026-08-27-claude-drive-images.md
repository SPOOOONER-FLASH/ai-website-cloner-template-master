# Claude — 从 F 盘补 38 个产品的图片

| | |
|---|---|
| 范围 | `scripts/match-drive-folders.mjs`（新增）、`content/products/*.json`(38)、`public/images/products/`(+136)、`src/lib/content-health.ts` |
| 结果 | **无主图产品 113 → 75** |

## 为什么要新写一个匹配脚本

`import-drive-images.mjs` 早就写好了（含 PSD 去水印、雷茵排除、STAHLOCK 检出丢弃），
但它读的 `drive-match.json` 只收录了**已经有图**的产品，跑起来是 0 命中。
而且它假设路径是 `ROOT/<分类>/<型号>`，缺图的这批藏得更深：
`2-球锁/大档盖球锁/5874 ACET便宜货不锈钢/图/`。

新脚本递归走 907 个含图目录，按**归一化型号 token**匹配路径中的任意一段（不只是叶子名），
因为客户把网图放在 `图` 子目录、重拍放在 `2026新拍/<型号>/`。

匹配规则里最要紧的一条：**token 后面不能再跟数字**，否则 `587` 会把 `5874` 吃掉——
那是另一个型号，不是它的变体。

## 结果

38 个匹配，136 张图（132 张从 PSD 干净渲染，4 张从 JPG），丢弃 16 张仍带 STAHLOCK 的。
36 张标了 `sourceNote: "2022-watermarked"`。雷茵、STAHLOCK、诚信通、原图目录全程排除。

## 拍摄年份怎么找回来

甲方要求带水印的旧图先上、但要能批量定位重拍。`/status/` 加了一行
**「图片是旧拍摄，待重拍」77 / 431**，读的就是 `ImageRef.sourceNote`。
重拍到位后按这个字段批量替换即可，不用一张张看图。

## 还差 75 个，多数不是找不到而是不能用

未匹配的 74 个里绝大多数是**同型号的不同表面处理**：`607 ABET`、`607 BNET`、`607 FET`、
`607 WBK`、`607 WLET` —— F 盘只有 `607 PBBK`。
**不能拿抛光黄铜的照片去配古铜色的页面**，表面处理是买家一眼就看的东西，
放错等同于填错规格。要么甲方补拍，要么这些型号合并成一个带变体的页面。

## 验证

`npm run check` 通过（23 测试 / 472 页）。`deploy:prep` 通过。
顺带修正 `/status/` 合规区的说明——原文还写着「四份报告」，其中一份已因归属 KALE 撤下。
