## 一、主匙填写表（已上线）

学自 MIWA 的 キーシステムプラン入力シート。**关键不是表格，是第三张「記入例」**——
空表会让没做过主匙的买家卡住，填好的样例让他照着填。大多数供应商只给空表。

四张工作表：门表（目录派生的下拉）、自由格式（买家已有门表就直接贴）、
填好的范例、隐藏的查找表。范例是三层小楼，因为文章说大多数建筑只需三级 ——
范例演示五级等于悄悄推荐五级。范例里特意留了两行买家最常填错的：
G-04 只有总钥匙能开（不写明的门会默认继承楼层主钥匙）、
2-07 把承包商钥匙也计进钥匙数（没数进去的钥匙是重画钥匙表的常见原因）。

`npm run sheet:masterkey` —— Node 出数据、Python 出文件格式，与 `build_spanish_workbook.py`
同一分工。新增 `planning` 下载类别，TypeScript 的 `Record<DownloadKind,string>` 立刻
逼出 `downloads.ts` 的镜像遗漏。文章新增结构化 `attachment` 字段（正文是纯段落不渲染链接）。

⚠ 顺带修了文章一处错：原文写锁芯长度「45, 47, 54, 56, 65, 70 and 80mm」，
**漏了 60 和 90**（目录里 60 有 5 个型号、90 有 4 个）。而且 45 条已发布锁芯里只有 10 条
把长度写成规格行。原文当初对 54/56 就是从型号数字推的，却漏了 60/90，内部不一致。
已补齐九个长度并写明依据与缺口。**这条推断只适用于锁芯长度，不要扩展到轴距或中心距。**

### 三个踩到的坑，都由测试或核对抓到

**1. viewBox 算错，56 张全部被裁掉下面那个孔。**
第一版把画布高度按边距算，产出 720×300 的框套着 570 高的图形。**SVG 不会报错，它只是裁掉**，
而一张被裁的开孔图是这个站上唯一可能把人送到错误孔位的图。已修，并写成测试
（逐张比对实际绘制范围与 viewBox）。

**2. 组件嵌错层级，本来会永远不渲染。**
一开始把 `DoorPreparation` 嵌在 `ProductDrawing` 里，而后者没有外形图就 `return null`。
核对发现**两个集合零重叠** —— 56 张开孔图对应的产品**没有一个有外形图**，因为拉手公布
固定中心距、锁体公布壳体几何，是两套配方两批产品。已改成同级渲染。

**3. 我先前对甲方说的「135 条能出开孔图」是错的，已在本轮当场更正。**
那个数是按「有轴距或中心距 + 至少一项开孔相关标签」粗筛的，把 `Door thickness`、
`Chassis` 这类也算进去了。真正要的是**孔径 + 位置**两者俱全，HYDE 是 0。

## 三、没有做、以及为什么
