# 2026-09-04 · Claude · 配置器双栏目上线 —— 以及它此前从未渲染过

## 先说最重要的一件事

**上线以来 `/configurator/` 和 `/es/configurator/` 从来没有真正显示过。**

生产环境这两页的正文一共 293 和 309 个字符：

> Find the right model … Every option shown leads somewhere — you cannot reach an
> empty result. Already know what you need? Filter the catalogue directly.
> **Loading the catalogue…**

工具本身一次都没出现过。页面把组件包在一个普通的 `<Suspense>` 里，而在
`output: "export"` 下，`useSearchParams()` 所在的 Suspense 边界没有服务端可以流式
解析 —— fallback 就是最终状态，永远停在那里。

**为什么一直没被发现。** 所有自动检查都是通过的：构建成功、路由存在、链接可点、
死链审计找得到这一页、页面有 h1 有段落。**任何"找缺失页面"的检查都看不见一个存在
但空白的页面。**

GEO 审计其实测到了：`/configurator/` 得 35 分、可引用数字 0.0，全站最差。
我把那个数字读成了"新页面文案还薄"。它实际上是**一个内容从未渲染过一次的页面**。

和搜索框回车那次是同一个教训：「能不能构建」和「用起来是不是死的」是两个问题，
而我只问了其中一个。

**修法**：`ProductFinderClient` 早就用了正确做法，只是没有用在同样需要它的组件上。
新增 `ConfiguratorClient`，`dynamic(..., { ssr: false })`，去掉 Suspense。

## FSB 研究：他们的"动效"到底是什么

按甲方要求把那个深链每个按钮点了一遍，读了 DOM：

| 我以为的 | 实际测到的 |
|---|---|
| 复杂动画库 | `animationNames: ["spin", "enter"]` —— 一个加载转圈，一个挂载淡入 |
| 定制缓动 | 全是 Tailwind 默认：`all 0.15s cubic-bezier(0.4,0,0.2,1)` |
| 每种配置一张渲染图 | **Cloudinary 图层叠加**：`l_product-finder:dk:ros:lo:dk_ros_lo_lse_0105/…` |

**他们的产品图是按部件在 CDN 上实时合成的**，一层玫瑰座、一层执手、一层表面处理码。
换个表面处理 → 图层 id 变 → Cloudinary 返回新合成图。这才是"动"的来源。

真正难抄的那一部分不是代码，**是写作**：他们每一个选项都带一句人话解释
（"FSB ASL® — 用于日常使用频度低到中等的普通室内门"）。

### 我们能学什么，不能学什么

**不能**：我们的产品图是整机棚拍，不是部件图层，合成不了。

**能，而且我们的版本更有用**：FSB 当着你的面拼装的是一个**货号**
（`12 · 1003 · 02310 · 0105`）。我们拼装的是**门五金明细表上的那一行**——
这些买家真正要写进 schedule 的句子，答完最后一题可以直接复制走。

未回答的位置保留占位符 `—` 而不是省略，所以这一行从第一次渲染就是最终形状，
读者不用数步骤就知道还剩几个决定；同时它不会随着回答一格一格往右长
（`.spec-slot-empty` 有宽度下限）。

## 双栏目

甲方要求："在 finder 下面开两个栏目"。

做成**两个真实路由 + 一个共用切换控件**，不是一个客户端 tab 组件。
静态导出下客户端 tab 会让其中一种模式没有自己的 URL —— 没法发邮件、没法被收录、
没法作为回访地址。两个路由本来就各自存在、各自排名，这个控件只是让它们互相看得见。

当前那一侧渲染为带 `aria-current="page"` 的链接，不是禁用按钮：
一个按下去没反应的可见控件正是 Clarity 在页脚查出来的 dead click。

顺带把 "Guided selection" 那个 eyebrow 删了 —— 它只是把下面的标题又说了一遍，
而切换控件占同一行并且真的在做事。

## 选项解释：一次修两个问题

配置器问"你要指定什么？"然后给出 `night-latches-rim-locks`。
懂行的人知道，**但这个工具存在的全部理由就是给答不上 Finder 问题的人用的**。

现在 34 个类目和子类目每一个都带一句定义，中英西双语，且有测试兜底：
新增一个类目而没写定义会**测试失败**，不会以裸 slug 的形式上线。

这些是**行业术语的定义，不是对我们产品的声明**。"插芯锁体嵌入门扇边梃开出的槽里"
对古往今来每一把插芯锁都成立。另有一条测试断言这些句子里不出现
EN 1125 / ANSI / certified —— 和 `stahlock-cited-policy.mjs` 对规格行的规则同一条。

### 但它们原本一个字都进不了 HTML

配置器是 `ssr: false` 的，所以卡片上那些写作在 HTML 里不存在。
**全站写得最好的一页，恰恰是审计里最差的一页，因为它是隐形的。**

所以同一份常量也由服务端渲染成一个术语表（`HardwareGlossary`），
用 `<dl>` 标记 —— 术语和定义哪一半是哪一半，机器读得出来，从一堆 `<div>` 里只能猜。
每一条链到它所定义的那个类目页。

|---|---|---|
| `/configurator/` 正文 | 293 字符 | **4,559** |
| `/es/configurator/` 正文 | 309 字符 | **5,011** |

## meta description：47% 是同一句话

量出来的：**全站 meta description 文本的 47% 是四句样板中的一句**，
410 / 435 条以它结尾。Google 只渲染约 155 字符，所以搜索者读到的一半以上，
是他刚在上一条结果里读过的同一句。

与此同时 **217 个产品带着人工核对过的 summary**，说清这东西是干什么的，
而这些句子一句都没进过 snippet。

修法就是把它换个位置：**能区分产品的那句话，放到重复的那句话原来的位置**。
样板没有删掉，只是排到最后去领剩下的字符 —— 那才是样板该待的地方。

**47% → 33%。**

### 两个我自己制造又修掉的缺陷

1. **第一版把 summary 无条件塞进去，让长度上限去处理溢出**，结果 snippet 变成
   `…applications. A ke…` —— 一句话写了两个词就断了。**那比它取代的样板更糟：
   重复的句子至少是完整的。** 现在是整句放得下才放，放不下就不放。

2. 修完发现还有 10 条以 `…` 结尾 —— 那是**原有**的收尾逻辑
   `base.slice(0, DESC_MAX - 1) + "…"`，一直在把词切成两半
   （"For timber fire door, steel fire door appli…"）。改成**整句整句地丢，
   而且每丢一句就重试一次样板**：丢句子是为了把省出来的字符花掉，不是为了返回一个光秃秃
   的开头。EN 0 条、ES 0 条截断，0 条重复。

## 图片与 sitemap

甲方："记得图片都要 alt 和加 sitemap"。

- **alt 已经是满的**：360 张主图、1,189 张图库图、35 段视频及其封面，**缺失 0**。
- **sitemap 之前只列主图** —— 1,584 张里只给了爬虫 360 张。这一行买家会先用

  往往是第三张图，不是主图。现在全列：**`<image:image>` 3,152 条，`<video:video>` 70 条。**

## 其他

- `/es/product-finder/` 新建。切换控件在西语侧要指向一个存在的页面，否则它就是一个
  装成功能的死链。**渲染的是同一个组件带 `locale="es"`，不是第二份实现** ——
  两份实现在下一次加 facet 时就会分叉，而分叉只有读西语的人看得见。
- `FACET_LABELS_ES` 用 `Record<FacetKey, string>` 类型：加一个 facet 而不补西语会**编译失败**。
- eslint 忽略 `.agents/skills/**` 与 `.claude/skills/**`。装进来的 skill 里有 15 个 `.cjs`
  用 `require()`，`npm run check` 一直卡在没人写、也不该改的文件上。
  另外两条路是改会被 `npx skills add` 覆盖的第三方代码，或者为全项目放宽规则。
