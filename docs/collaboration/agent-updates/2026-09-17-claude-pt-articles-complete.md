### 补上了 seoTitlePt / seoDescriptionPt（35 × 2）

`npm run audit:pt` 之前报葡语文章 60%，缺的就是这两个字段。后果不是小事：
**每个 /pt/ 文章在葡语搜索结果里显示的是英文标题** —— 正文翻好了，
而搜索者唯一看得到的那一行没有。

这两个字段不是 titlePt / summaryPt 的复制。它们做的是另一件事：
标题是读者在页面上看到的句子，seoTitle 是结果列表里那一行，围绕别人会打的词
而不是围绕一个读起来顺的句子。英文那一对就是例子 ——
「Push Bar or Touch Bar: Which Panic Device Your Door Needs」对
「Push Bar vs Touch Bar Panic Exit Device — Which to Specify」。

第一遍照着英文译，35 条里 23 条超过 165 字符（结果列表大致在这里截断），
因为同样内容葡语比英语长 15–20%。**第二遍是重写而不是截断** ——
从末尾砍掉一个从句会留下一个断掉的句子；重写保留能带来点击的那半句，
丢掉装饰的那半句。现在 34 条在 165 以内，一条 166。

审计结果：

```
news articles     35    ES 100%   PT 100%
```

### 问答块的语言：标题跟着内容走

正文翻成葡语之后，问答块暴露出一个新问题：`articleFaqItems` 对 pt 回落英文，
而 `articleFaqHeading` 按页面语言返回葡语标题 —— 于是页面渲染出
「Perguntas frequentes sobre este tema」下面挂着四个英文问题。

**葡语标题引出英文内容，读起来像渲染 bug 而不是像缺口。** 这正是正文回落规则
要避免的那件事，只是下移了一个元素。

新增 `articleFaqLocale()`：回落时标题跟着回落，那一段还带上
`lang="en"` —— 屏幕阅读器会换音，搜索引擎不会被告知英文是葡语。
这样那一块就明显是葡语页面里的一段英文插入，是诚实的，也是会被修的状态。
