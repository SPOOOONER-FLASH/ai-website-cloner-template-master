## 一、甲方问的折中方案：能不能保留 AI 影调，只把产品修对

做了实验，结论可以一句话说完：**打光和色温可以对齐，机位不能。**

`compose-scene-plate.mjs` 把真实抠图放进场景，并做三件纪律允许的事——曝光匹配、
白平衡向场景轻推、沿场景光向的柔和明暗渐变（dodge & burn，像素顺序不变，
不可能凭空造出原图里没有的高光）。投影两道：接触影和投射影，都由零件自身轮廓生成。

**第一版有一个必须记下来的错误。** 曝光增益乘上暖色偏移后直接交给 `linear()`，
在暖场景 + 抛光黄铜上红绿两通道双双溢出，执手变成荧光黄——一个买家订不到的表面处理。
**改产品的颜色和改它的孔位是同一类错误：都有人照着下单。** 现在增益向量做归一化，
最大通道增益不超过 1.06。

**剩下的问题不是 bug，是物理。** 目录照片是正面平光拍的，场景是俯视 45° 拍的。
二维照片无法在深度上旋转，所以零件永远站在一个和台面不同的透视里。
样张放在 `tmp/claude-scene/`，一眼能看出来。

可行的路径因此是**反过来定场景**：场景要按我们的机位来拍/生成，不是反过来。
可用场景的简报很窄——单一柔光源、略偏左上、无第二主光、无硬轮廓光；台面与相机水平线齐平，
不俯拍；画面里没有任何金属；局部反差低。

## 二、给译者的复核表

`npm run es:sheet` 一条命令重跑，输出 6 个分页的 xlsx。**不要手改 xlsx**，改
`es-review-chinese.mjs` 或术语表然后重跑。

| 分页 | 行数 | 说明 |
|---|---|---|
| 0 说明 | — | 中西双语，给译者看 |
| 1 表面处理 | 20 | **最高杠杆**：20 条术语替掉目录里 84 种写法 |
| 2 缺译 | 55 | 今天西语页面上真实可见的英文 |
| 3 术语复核 | 774 | 已有译法，按影响页面数降序 |
| 4 页面文案 | 168 | 手写整句 |
| 5 尺寸参考 | 224 | 纯数字，分出来不占译者时间 |

**发现一个结构问题值得单独处理。** `SPEC_VALUES_ES` 按整串匹配，593 条里有 95 条是
逗号连接的表面处理长串；单个表面处理名（`Polished Brass (PB)` 等）在术语表里**一条都没有**。
后果是每出现一种新的表面处理组合就多一条缺译。正确做法是按 token 查表再重新拼接——
20 条决定一次，此后任何组合都成立。表面处理那一页就是按这个前提做的；
`localiseProductValues()` 的改动等译者定稿后再落。

另外目录里 `Finish` 字段本身写法不统一（84 种拼法对应约 20 个表面处理，
`Antique Brass (AB)` / `antique brass` / `Antique brass (US5)` 是同一个）。
这是内容清洗，与翻译无关，另计。
