## 一、最贵的一条：**联系表单一次都没成功过**

`InquiryForm` 发信要一个 Web3Forms 的 access key（`NEXT_PUBLIC_W3F_KEY`）。
这个变量**从来没有配置过** —— 构建产物里它还是运行时查找而不是内联的字符串：

```js
let a = t.default.env.NEXT_PUBLIC_W3F_KEY?.trim();
if (!a) { b("error"), j(d.unconfigured); return; }
```

Next 会在构建时把设置过的 `NEXT_PUBLIC_*` 内联成字面量。它没有内联，
说明构建时它不存在 —— 浏览器里那个对象是空的，所以**每一次点「发送」都走失败分支**。

### 而失败时给访客看的是什么

```
The inquiry service is not configured yet.
Add NEXT_PUBLIC_W3F_KEY before publishing this form.
```

一个卖「我们很严谨」的站，对着买家的询盘回了一句部署备忘。

### 代价

05:40  再点 —— 连续死点击与暴怒点击

同一天土耳其那位点了两次「Send inquiry」（01:34、01:51）。沙特那位在表单上死点击。

   `localised()` 于是给 `pt` 回退英文。巴西买家看到的字段名全是英文。已补葡语。

## 二、切换语言要点五次

Clarity，9 月 17 日，西班牙，从 Google 进英文首页：

```
00:21, 00:24, 00:25   点语言选择器 "ES · PT"
00:28                 选中 "Español"
```

十五秒、五次点击，只为做这个控件唯一存在的那件事。原因在标记里：
**`ES · PT` 看起来是两个链接，其实是一个按钮**，点下去弹出一个面板。
读者点了 "ES"，弹出面板，不是他要的，再点一次关掉。

现在那两个语言码**就是它们看起来的样子**：指向本页该语言版本的真链接，一次点击。
地球图标仍然打开完整面板（国家与联系人，另一件事）。

服务端渲染的 `<a>`，所以每个页面又多了两条指向自己译本的可抓取链接。

`triggerLabel()` 因此退休（它只为渲染那个字符串而存在），
它守的不变式现在由 `languageChoices` 的那条测试守着。

## 三、西语页面的英文：40 条 → 3 条

新增 `scripts/audit-es-pages.mjs`（`npm run audit:es:pages`）。
**对照组换成葡语** —— 葡语今天到了 0 英文，所以它现在是可用的参照：
/es/ 有、英文有、葡语没有，才报。

首跑：**146 个页面、40 条**。绝大多数是一个形状：

```
Zinc Alloy/304 Stainless Steel
Iron+Stainless Steel
Chrome Plated (CP), Polished Brass (PB), Satin Nickel (SN)
```

葡语全都渲染得出来，西语一条都不行。原因是**同一个问题走了两条代码路径**：

```ts
if (locale === "pt") return values.map(localisePt);   // 按分隔符拆开，逐段查表
if (locale !== "es") return values;
return values.map((v) => SPEC_VALUES_ES[v] ?? v);      // 整串查表，必然查不到
```

拆分逻辑从来就不是葡语专有的。现在是一个函数，两种语言都用它，并且：

- **逗号也是分隔符**（成品表面是写成列表的），
- **`Antique Brass (AB)` 是「名字 + 代码」** —— 翻名字，代码原样放回。
  代码是买家要写进采购单的标识符。
- 分隔符的空格现在在捕获组**里面**，所以 `A / B` 真的还原成 `A / B`。
  旧注释声称做到了，其实一直没有。

西语补上 `FINISH_NAMES_ES`（41 条）与 `MATERIAL_NAMES_ES`（48 条），
对齐葡语早就有的两张表。

### 存量的 specsEs 怎么补的 —— 没有重跑那个禁用的生成器

`AGENTS.md` 禁止对本目录跑 `translate-products-es.mjs --write`：
2026-09-11 它把 830 行手工改好的西语**退回了英文**。

所以写了 `scripts/fill-spec-values-es.mjs`，规则窄到不可能造成回退：

> **只有当某一行的西语值与英文值逐字节相同时才写。**

差一个字符都不碰。它**没有能力**回退任何东西，因为它只碰那些根本没被翻过的行。
85 行被补上。

⚠ 第一版按**下标**配对英西两个数组，于是跳过了所有长度不等的记录 ——
072 有十条英文规格、六条西语规格，而审计追的那一行正好在被跳过的集合里。
改成**按标签配对**：标签才是「这是哪个字段」的答案。

剩下 3 条：版权行（各语言相同）、`HYDE Argentina AR-4`（产品线专名）、
以及一条已修的。

## 四、审计看不见的东西，各修了一处

| 盲区 | 找到的 | 怎么找的 |
|---|---|---|
| 两个页面审计都**跳过单个词**（一个词可能是型号或表面码） | 葡语联系页的小标题写着 `Dirección`，面包屑写着 `Certificación`，compare 页标题结尾 `Especificaciones` | 按**西语词形**（-ción、-miento、-illo、ñ）扫葡语树 |
| 页面审计比较**词**，一行不存在就没有词可比 | 072 的西语规格表只有 6 行，英文和葡语都是 10 行 —— 缺的正是中心距、方轴、锁芯孔、配用型号，**恰好是判断能不能装的那四条** | 数行数 |

后者已写成测试 `src/data/spec-table-parity.test.ts`：
**任何译文的规格表都不得短于英文的。** 断言长度而不是断言标签对齐 ——
表格合并或重排是合法的，但「完整」和「更短」不能同时成立。
