# 2026-09-28 · Claude · 按浏览器语言提示的一行横幅（不是 BWT 那种弹窗）

甲方看到 BWT 的首访国家选择弹窗，问要不要给 HYDE 也做一个，然后说「做，根据浏览器语言来提示」。

## 为什么不是弹窗

BWT 那个是**国家**选择：它把访客送到不同法人实体的独立站点，产品线、经销商、价格都不同，
所以必须先选。HYDE 是**一个站、一份目录、十种语言**——德国买家和奥地利买家看到的产品一样，
只有语言不同。弹窗要一次点击，换不来任何信息。

三个具体代价：Google 从 2017 年起把首屏被对话框遮住算作 intrusive interstitial，而本站
正在做 hreflang / llms.txt / 结构化数据；B2B 访客多半从搜索和阿里巴巴直接落在产品页，
首页弹窗拦不到他们；国家下拉还会暗示按国家分站分价，而我们没有——`locale-picker.ts` 当初
拒绝照抄 FSB 面板就是同一个理由。

## 做了什么

`src/components/site/LanguageSuggestion.tsx`，挂在全部 10 个 locale 的 layout 里
（`(en)` / `es` / `pt` 手写三个，其余七个改的是 `scripts/scaffold-locale-routes.mjs` 模板后重新生成）。

一行安静的通知条，位于 sticky header **之上**、正常文档流里：它提供，不遮挡。

    [ Diese Seite auf Deutsch ansehen ]                              [ Schließen ]

- 只在浏览器首选语言与当前页面不同、**且这一页在那个语言里真实存在**时出现。
  `languageChoices()` 已经知道 `samePage`，为 false 就什么都不说——与隔壁 hreflang 策略同一条规矩：
  链接落不到它声称的地方，比没有链接更糟。
- 文案全部是**被提供的那个语言**，`lang` 和 `dir` 跟着设，阿拉伯语整条右对齐。
- 关闭后记进 localStorage，读写都包了 try/catch（隐私窗口会抛）。

## 三件在浏览器里才发现的事

**一、`.layout` 是命名网格，不是容器。** 我一开始把 `layout` 和 `flex` 写在同一个元素上，
`display:flex` 覆盖了 `display:grid`，这一行就掉出了内容栏体系、贴着视口边缘。
正确写法是 `layout` 包一层，`col-content` 放在里面——`.layout > *` 的规则本来就写着这件事。

**二、`requestAnimationFrame` 在隐藏标签页里不跑。** 第一版用 rAF 延迟判断，
结果在后台标签页打开的页面（买家一次开三个产品页的常见方式）永远不显示，直到被切到前台。
改成 `setTimeout`，与 `PromoDialog` 同一个写法，它的注释里也解释了为什么不能在 effect 体内
同步 setState（lint 会拒绝，也会级联渲染）。

**三、原来的两段式文案在手机上占了 108px。** 「这一页也有德语版。」＋一个「查看德语版」链接
是同一件事说两遍，375px 下折成三行、吃掉视口的八分之一。
改成一条链接承载整个意思，德语、俄语、日语都是 **50px 一行**。

## 布局位移，如实说明

它在正常流里，出现时下方内容下移约 50px。这是真实的 CLS，约 0.05（阈值 0.1），
**且只有看到它的人才付**——浏览器语言与页面一致的读者根本不渲染它。
备选方案更差：固定在底部会撞上已经占着 `bottom-16` 的促销条；
把十个候选都预渲染再用脚本显示一个，等于在每页 markup 里塞九句误导性的
「本页也提供……」给爬虫读；给所有人预留空间则是让多数人替少数人买单。

## 验证的边界（重要）

**`preview_start` 跑的是主仓库，不是我的 worktree**，所以开发服务器里看不到这个组件——
我一度以为是代码问题，查到 body 宽度为 0、脚本里搜不到组件才定位到。
最终验证方式是：用 `canton-hyland-static` 服务主仓库已构建的 `out/`，
把组件的真实 markup 注入真实 CSS 后测量与截图。因此**「组件在真实路由里挂载后的表现」
仍需在主仓库拉到这次改动后看一眼**，样式和文案已按上表量过。

## 2026-09-29 补：已在线上真实路由验完，上面那条待办可以划掉

上线之后在 `cantonlock.com` 上用真实浏览器（`navigator.language = en-US`）逐条验：

| 行为 | 实测 |
|---|---|
| 德语页上出现 | `/de/` → 「View this page in English」 |
| **深层页给同一页，不是首页兜底** | `/de/products/floor-springs-and-pivots/` → `/products/floor-springs-and-pivots/` |
| 标签语义 | `<aside lang="en-GB" dir="ltr">`，链接带 `hreflang="en-GB"` |
| 关掉之后消失并记住 | `localStorage["hyde.language-suggestion.dismissed"] = "1"`，刷新不再出现 |
| **语言一致时不出现** | 清掉标记后，英文浏览器打开 `/products/`，横幅不渲染 |

第二条是这个组件真正的价值所在：一个把德语读者从产品页扔回英文首页的"提示"
比不提示更糟，因为他丢了自己正在看的那一页。

`lang`/`dir` 挂在横幅上而不是继承页面，是给读屏软件的：它要用英语发音念这句英语，
而整页是德语。
