# AR-4 三个旧网址的 301 跳转生效：服务器上一条命令（2026-10-09）

**这份 Word 由仓库里的同名 markdown 生成，改内容请告诉我，不要直接改 Word。**

## 为什么要做

AR-4 合并后，三个旧锁体页（110、140、1121 lock case）并进了 AR4 的三条记录。旧网址要 301 跳到新页，否则有人从 Google 或旧链接点进来会看到 404。

跳转规则已经写进代码、随网站推上去了，但 nginx 读的是服务器上另一个文件夹里的配置，`git pull` 不会更新它。所以要在服务器上跑一次下面这个脚本：复制 → 备份 → 测试 → 重载 → 验证，一条命令做完。

## 操作步骤（宝塔面板，约 3 分钟）

**① 打开宝塔终端**：左侧菜单最下面的「终端」。没有的话去「软件商店」搜「终端」装 Web 终端。

**② 粘贴这一行，回车：**

```bash
bash /www/wwwroot/cantonlock.com/deploy/install-nginx-redirects.sh
```

> 如果提示找不到文件，先跑这一行找到路径，再把上面的路径换成它打印出来的那个：
>
> ```bash
> find /www/wwwroot -maxdepth 3 -name "install-nginx-redirects.sh" 2>/dev/null
> ```

**③ 成功时最后一行是：**

```
All redirects live. Now purge Cloudflare — it caches 301s.
```

**失败时**脚本会自己把旧配置还原、不重载，网站不受影响。把整屏截图发我。

**④ 去 Cloudflare purge。** Cloudflare 会缓存 301，不 purge 的话浏览器里看到的还是旧结果。
