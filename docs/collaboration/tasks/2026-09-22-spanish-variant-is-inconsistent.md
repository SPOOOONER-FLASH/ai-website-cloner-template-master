# 西语变体：声明的是拉美，实际是混的，而且混在同一个产品页里

客户 2026-09-22 问：「我们要欧西还是南美西还是墨西？」

答案不是三选一。**我们现在三个都不是 —— 我们是混的。**

## 实测（`tmp/claude-seo/es-split.mjs` 可重跑）

每格是「欧西次数 / 拉美次数」：

| 词对 | `es-glossary.ts` | 产品页 `specsEs` | 文章 `bodyEs` |
|---|---|---|---|
| manilla / manija | 9 / 18 | **179 / 129** | **260 / 42** |
| pomo / perilla | 6 / 0 | 69 / 0 | 42 / 0 |
| tirador / jaladera | 5 / 0 | 51 / 0 | 18 / 0 |
| cerradero / contrachapa | 6 / 0 | 155 / 0 | 101 / 0 |
| retranqueo / entrada | 1 / 6 | **0 / 474** | **0 / 119** |

## 三个发现

**1. 声明的政策只有一条真的执行了。** `es-glossary.ts` 的文件头写着
「The register is Latin American trade Spanish… Latin wins」。实际只有
`entrada`（backset）这一条守住了 —— 474 个产品行，`retranqueo` 零。

**2. 其余三对全部漂移到了欧西。** `pomo`、`tirador`、`cerradero` 在词表、产品页、
文章里都是欧西写法，拉美对应词一次都没出现。这不是翻译错误，是政策写下来之后
没人再对照过。

**3. `manilla` / `manija` 在同一批产品页里就是混的** —— 179 对 129。
不是「产品页一种、文章另一种」，是**产品页内部自己就不一致**。一个买家连着看
两个产品页会看到两个词指同一个东西。

## 为什么这件事值得单独做

修它要动约 **439 处** `manilla → manija`（产品页 179 + 文章 260），外加 `pomo`、
`tirador`、`cerradero` 三对。这正是 AGENTS.md 里
「A regenerator that has fallbacks will quietly undo work it cannot see」
警告的那种规模 —— 不能塞进别人的改动里，要有自己的 diff 给人读。

## 建议的方向（不是决定，等客户定）

**倒向拉美**，理由是数据而不是偏好：

| 依据 | 数字 |
|---|---|
| 词表文件头已经这么声明 | 写于更早，理由已记录 |
| `entrada` 已经是拉美且覆盖最广 | 474 行，改回欧西代价最大 |
| 拉美点击率高于西班牙 | 秘鲁 13%、乌拉圭 37.5% vs 西班牙 5% |
| 西班牙展示量领先 | 西班牙 60 展示 vs 秘鲁 23 |

最后一行是反方证据，**不要假装它不存在**：西班牙的展示量确实更高。但展示是排名
给的，点击才是人给的，而拉美三国的点击率是西班牙的 2.6 到 7.5 倍。

## 一个不分叉的替代方案

不改现有文字，只在 `es-glossary.ts` 里给这五对词**同时登记两种说法**，让墨西哥
买家搜 `jaladera` 或 `manija` 也能命中。成本极低，但它只解决「搜得到」，
不解决「同一页里两个词指一个东西」这个专业感问题。

**两件事可以都做，但顺序是先统一、再补同义词。** 反过来只会把混乱固定下来。
