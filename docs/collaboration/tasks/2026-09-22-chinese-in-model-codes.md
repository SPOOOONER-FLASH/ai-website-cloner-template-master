# 25 个产品的型号字段里混了中文

写标题生成器时发现：25 个合页产品的 `model` 字段带中文变体后缀，直接漏进了
英西葡三语的标题和描述。对一个西方买家，英文标题里出现中文看起来像页面坏了。

| 后缀 | 个数 | 含义 |
|---|---|---|
| 美标 | 9 | 美标尺寸 |
| 圆角 | 5 | 圆角叶片 |
| 偏轴 | 4 | 偏心轴 |
| 双钉防盗合页 | 2 | 双钉防盗 |
| 单钉防盗合页 | 2 | 单钉防盗 |
| 拉手 / 中轴 / 焊头 | 各 1 | 拉手 / 中轴 / 焊接合页头 |

## 当前的临时处理

`scripts/build-product-titles.mjs` 里有一张 `MODEL_SUFFIX_GLOSS`，**只在显示层**
把这些后缀译成对应语言。型号字段本身没有改。

例：`4x4x3.0-4BB双钉防盗合页` → 标题显示 `4x4x3.0-4BB Twin-Pin Security Ball Bearing Hinge`

## 为什么没有直接改型号

型号是**订货依据**。改它会牵动 URL、订单记录、客户手上的旧报价单、
`legacy-redirects.conf` 里的映射。这不是一次查找替换能干净做完的事。

## 真正的修复（待客户决定）

三个选项，成本递增：

1. **保持现状** —— 显示层翻译已经解决了 SEO 问题。型号在内部仍是中文后缀。
   成本零，代价是工厂和网站两边的型号写法不一致。
2. **加一个 `modelDisplay` 字段** —— 型号不动，另存一个英文展示名。
   成本小，需要页面组件也读它。
3. **规范化型号** —— `双钉防盗合页` → `-TPS` 之类，并加 301。
   成本最大，但只有这个能让工厂、网站、订单三边一致。

**建议 2**，因为它既解决了展示，又不动订货依据。但要先问工厂：这些后缀在他们
内部是不是正式型号的一部分。如果是，选项 3 就不能做。
