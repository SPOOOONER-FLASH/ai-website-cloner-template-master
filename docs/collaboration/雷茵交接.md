## 5. 两台电脑怎么协作（重要）

甲方带走 86132 那台，johns 这台也还在。**git 是两台之间唯一的通道。**

**唯一的禁忌**：仓库里提交了 21,000 多个构建产物（`out/` + `out-rayen/`）。
两台都改都构建都推的话，后推的会被 git 拒绝，然后 `git pull` 会**逐文件合并这两万个
产物**，合出来是两次构建的混合物 —— 一部分页面来自 A 那次，一部分来自 B。
**全程不报错**，因为每个文件单独看都没冲突。

**规矩**：只在一台上改和构建，另一台只 `git pull` 不改。
详见 `docs/collaboration/CLIENT-RUNBOOK.md` 第 7、8 节（写给甲方看的版本）。

## 6. 暂存的教训，别重犯

**不要用 `git add -A -- <目录>`。** 这个仓库是多个会话共享工作树的。
2026-09-09 我用 `git add -A -- content` 暂存，把另一个会话**正在写、还没写完**的
五个产品 JSON 按了快门，提交里是截断的、解析不了的内容。
是提交完看 `git status` 还剩 39 个改动、去查「为什么还没干净」才发现的。

**按明确路径暂存**：`git add -- path/a path/b`。
动别人的文件之前**先 `cp` 一份备份**（我修的时候 `git show HEAD~1:file > file` 在文件
不存在时报错退出，而 shell 重定向已经先把文件清成 0 字节，靠备份才救回来）。
