# 四个数据看板改用 API 自动拉数（2026-10-25）

你的问题：「Bing Webmaster 的 API 有了，其他的 API 怎么调用：GSC、Clarity、GA4」。

开通以后，不用再每周从四个后台手动导出 CSV。在 johns 电脑上运行一条命令，四个看板的数据就会自动拉进仓库，所有会话都能读到。

| 看板 | 用什么凭据 | 去哪里拿 | 大约耗时 |
|---|---|---|---|
| Bing Webmaster | API Key | 你已经有了 | 0 |
| Google Search Console | 服务账号（一个 JSON 密钥文件） | Google Cloud 后台 | 10 分钟，和 GA4 共用同一个 |
| GA4 | 同一个服务账号，加上媒体资源 ID | Google Cloud + GA4 后台 | 包含在上面 |
| Microsoft Clarity | API 令牌 | Clarity 后台 | 2 分钟 |

> **关于你发在聊天里的 Bing Key：** 密钥出现在聊天记录或截图里，就等于少了一层保护。建议这样做：先把它写进下面第 4 步的 `.env.local`，确认能拉到数据；然后在 Bing 后台点 API Key 旁边的刷新图标（Regenerate）换一个新的，把新的同样只写进 `.env.local`。以后所有密钥都**不要发在聊天里**，只写进这个文件。

## 第 1 步：建一个 Google 服务账号（GSC 和 GA4 共用，约 10 分钟）

1. 打开 https://console.cloud.google.com ，用管理 Search Console 的那个 Google 账号登录。
2. 页面顶部点项目选择框 → **新建项目（New Project）** → 名称填 `hyde-data` → **创建**。创建完，在顶部切换到这个项目。
3. 左上角菜单 → **API 和服务（APIs & Services）→ 库（Library）**：
   - 搜 `Google Search Console API` → 点进去 → **启用（Enable）**；
   - 再搜 `Google Analytics Data API` → **启用**。
4. 左上角菜单 → **IAM 和管理（IAM & Admin）→ 服务账号（Service Accounts）→ 创建服务账号**：
   - 名称填 `hyde-reader`，点 **创建并继续**；
   - 「授予此服务账号对项目的访问权限」**直接跳过**，点 **完成**。
5. 在列表里点刚建好的 `hyde-reader` → 顶部 **密钥（Keys）** 标签 → **添加密钥 → 创建新密钥 → JSON → 创建**。浏览器会下载一个 `.json` 文件。
6. 在 johns 电脑上新建文件夹 `C:\Users\johns\.secrets\`，把下载的文件移进去，改名为 `hyde-reader.json`。**这个文件不要放进仓库文件夹，也不要发给任何人。**
7. 回到服务账号列表，复制 `hyde-reader` 的邮箱地址，形如 `hyde-reader@hyde-data-xxxx.iam.gserviceaccount.com`。

**如果第 5 步提示「已禁止创建服务账号密钥」（organization policy）：** 说明这个 Google 账号属于某个企业组织，管理员禁止了这项操作。截图发我，我们改用 OAuth 方式。

## 第 2 步：给这个服务账号「只读」权限

**Search Console：**
1. 打开 Search Console，选中 cantonlock.com。
2. 左下 **设置 → 用户和权限 → 添加用户**。
3. 邮箱粘贴第 1 步第 7 项复制的地址，权限选 **受限（Restricted）**，点 **添加**。

**GA4：**
1. 打开 GA4，左下角齿轮 **管理（Admin）**。
2. 媒体资源一栏选 cantonlock → **媒体资源访问权限管理（Property access management）** → 右上 **+ → 添加用户**。
3. 邮箱粘贴同一个地址，角色选 **查看者（Viewer）**，取消勾选「通过电子邮件通知」，点 **添加**。
4. 还是在「管理」里，点 **媒体资源详情（Property details）**，右上角的 **媒体资源 ID** 是一串纯数字（不是 `G-RBTE7KF82P`），记下来。

## 第 3 步：Clarity 令牌（约 2 分钟）

1. 打开 Clarity，进入项目 **hyde**。
2. **Settings（设置）→ Data Export（数据导出）→ Generate new API token（生成新的 API 令牌）**，名称填 `hyde-reader`。
3. 复制生成的令牌。**它只显示这一次**，关掉页面就看不到了，没复制到就再生成一个。

## 第 4 步：把凭据写进 johns 电脑上的 `.env.local`

1. 打开 HYDE 仓库文件夹（`E:\cantonlock-hyde` 或你平时 `npm run release:hyde` 的那个目录）。
2. 根目录下如果已有 `.env.local` 就打开它；没有就新建一个，文件名就叫 `.env.local`。
3. 在文件**末尾**加上这几行，等号后面换成你自己的值：

```
BING_WEBMASTER_API_KEY=这里填 Bing 的 Key
GOOGLE_APPLICATION_CREDENTIALS=C:/Users/johns/.secrets/hyde-reader.json
GA4_PROPERTY_ID=这里填第 2 步记下的纯数字
CLARITY_API_TOKEN=这里填 Clarity 令牌
```

   路径里用正斜杠 `/`，不要用反斜杠 `\`。

4. 保存。git 会自动忽略这个文件，不会被提交或推送。

## 第 5 步：试一次

在仓库目录打开终端，运行：

```bash
npm run dashboards:api
```

**成功的样子：** 每个看板下面出现若干行 `✓ bing-GetQueryStats (123 rows)` 这样的结果，最后一行是 `→ docs/research/analytics/2026-xx-xx/api/API-SUMMARY.md`。

**某一项显示 `skipped — set ...`：** 说明 `.env.local` 里缺了那个变量，或者变量名拼错了。

**某一项显示 `✗ HTTP 403`：**
- GSC 出 403：服务账号还没加进 Search Console，或者刚加完，等 5 分钟再试；
- GA4 出 403：服务账号还没加进 GA4，或者媒体资源 ID 填错了。

两种情况都可以把整段终端输出截图发我。**截图前先确认里面没有显示任何密钥**：脚本已经把输出里的密钥打成 `***`，但你自己打开的 `.env.local` 窗口不要截进去。

## 以后怎么用

- 每周一跑一次 `npm run dashboards:api`，然后告诉任意一个会话「看板数据拉好了」，会话会读取数据、写结论。
- Clarity 接口只给最近 3 天的数据，想要每天的 Clarity 数据，就每天或隔天跑一次。
- 接口拿不到、仍要手动导出 CSV 的：Bing 的「AI 表现」页、Cloudflare AI Crawl Control、GSC 的「索引编制」和「生成式 AI 功能」。
