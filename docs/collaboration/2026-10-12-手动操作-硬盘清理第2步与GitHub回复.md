## 第 1 件 · 清空宝塔回收站（2 分钟，腾出 2.6G）

1. 宝塔左侧菜单点「文件」。
2. 文件页右上角点「回收站」。
3. 看一眼列表：都是 `cantonlockspooner.com` 的旧文件和几个 `_bt_` 开头的宝塔文件。确认没有你要的，点「清空回收站」。

清空后**无法恢复**。如果列表里有你想留的东西，或者找不到这个按钮，截图给我，先不要清。

## 第 2 件 · 清掉旧 GitHub 历史（粘贴 1 行，后台跑 10–30 分钟，腾出约 9–10G）

先做完第 1 件再做这一件，因为清理过程中要临时多占约 2.5G 空间。

宝塔「终端」粘贴这一整行，回车：

```bash
cd /www/wwwroot/cantonlock.com && [ "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)" ] && nohup flock -w 900 /tmp/cantonlock-deploy.lock sh -c 'rm -f .git/ORIG_HEAD && git reflog expire --expire=now --all && git -c pack.threads=1 gc --prune=now --quiet; echo "gc exit $?"' > /tmp/cantonlock-gc.log 2>&1 & echo 已开始
```

- 看到 `已开始` 就说明它已经在后台跑了，可以关掉终端。
- 什么都没打印，说明开头的安全检查没通过，什么也没删。截图给我。
- 网站在清理期间照常访问，只是这期间暂停自动更新。

## 第 3 件 · 30 分钟后检查结果（只查看）

```bash
cat /tmp/cantonlock-gc.log; pgrep -x git >/dev/null && echo 还在跑 || echo 跑完了; df -h /; du -sh /www/wwwroot/cantonlock.com/.git; git -C /www/wwwroot/cantonlock.com log -1 --oneline; du -sh /www/server/panel/data/hids_data/* 2>/dev/null | sort -h | tail -6
```

成功的样子：

- 出现 `gc exit 0` 和 `跑完了`
- `.git` 从 13G 降到约 2–3G
- `Avail` 从 3.6G 升到 12G 以上

如果显示 `还在跑`，过 10 分钟再贴一次。出现别的报错，截图给我，不要重试。最后几行是 `hids_data` 的明细，我看完再给你第 3 步。

## 第 4 件 · 宝塔入侵检测日志 7.5G（可选，腾出最多 7G）

`/www/server/panel/data/hids_data/log` 是宝塔入侵检测插件的日志，不是网站文件。下面这行只删 **7 天以前**的日志，最近一周的保留：

```bash
find /www/server/panel/data/hids_data/log -type f -mtime +7 -delete; du -sh /www/server/panel/data/hids_data/log; df -h /
```

如果你需要留着这些安全日志备查，就跳过这一件。

## 第 5 件 · 卸载没在用的自建 GitLab（可选，腾出约 3.4G）

`/opt/gitlab` 是 2026-08-17 装的 `gitlab-ce-19.2.2`，状态 inactive（没在运行）。网站现在用的是 gitlab.com 上的仓库，不用这一套。下面这行只卸载程序，它的数据目录（`/var/opt/gitlab`、`/etc/gitlab`）先留着：

```bash
du -sh /var/opt/gitlab /etc/gitlab 2>/dev/null; dnf remove -y gitlab-ce; df -h /
```

如果你记得这套 GitLab 是有人特意装来用的，就跳过这一件。
