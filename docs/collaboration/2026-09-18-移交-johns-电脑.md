### 2.3 合并规矩（这周踩了四次）

**永远不要 rebase 这个仓库。** `out/` 和 `out-rayen/` 是提交进仓库的构建产物，
一万五千个文件，rebase 会变成一场灾难。

正确姿势，这周和葡语会话抢了四轮之后定下来的：

```bash
git fetch origin
git merge origin/main --no-edit                 # 冲突基本全在 out/ out-rayen/
git checkout --ours -- out out-rayen            # 导出树一律 --ours
git add out out-rayen
git diff --name-only --diff-filter=U            # 必须是 0；非导出冲突要一个个看
git commit --no-edit
git push                                        # ← 先把 ref 抢下来
# 然后立刻完整重跑 build + prune + retain + test，再提交推送一次
```

**为什么要推两次**：`--ours` 那一版的 `out/` 只有自己这边的页面，对方那几个提交的成果
不在里面。先推是为了不再输掉下一轮竞争（重跑一次 build 要八分钟，这周因此连输三轮）；
第二次推的才是两边页面都齐的构建。**第二次推之前不要停下来做别的。**

⚠ 真冲突出现在 `content/products/*.json` 时（这周出现过一次，76 个文件）：
**取对方的**（保住他们加的语种字段），然后重跑自己那几份清单的 ingest 把摘要写回去。
不要反过来 —— ingest 能重跑，手写的翻译不能。

## 6. 上架一个新图册系列的标准流程（照抄）

```bash
# 1. 先看版式：整本的缩略图
node <切图脚本> "<PDF 路径>"          # 各图册的切法不同，见 scripts/catalogue-cutters/

# 2. 逐页读规格，写清单 content/rayen/<名字>.json
#    读不准的进 heldBack，不要编

# 3. 导入
node scripts/ingest-union-handles.mjs <清单文件名>

# 4. 图片流水线（顺序不能换，四步都是原地改写）
npm run rayen:images
#   = build-rayen-product-images（去水印）
#   → delocalize-drawings（日文→中文，按量出来的像素框）
#   → square-rayen-plates（补白成正方）
#   → brand-rayen-images（按语种打 RAYEN 标）

# 5. 衍生数据（不重算会过期）
node scripts/build-rayen-image-dims.mjs
node scripts/build-product-image-config.mjs
npm run assets:doorprep
npm run assets:watermark
node scripts/build-branded-editorial-list.mjs --write
npm run redirects:legacy

# 6. 中文镜像（英文是源，中文是生成的）
npm run rayen:mirror
npm run rayen:mirror:report     # 还有英文残留的值会列出来

# 7. 发布（见 2.2）
```

**每一批都要做的人工核验**：把切出来的图拼成一张联络表，**逐张放大看**。
自动检查只回答「有没有标记」，不回答「底下是不是那张图」。

## 7. 三条不能破的规矩（全部来自甲方本人）

1. **不写没有把握的尺寸。** 规格表里查不到的一栏是短横线，不是一个看起来合理的数字。
2. **不替甲方编货号、编颜色名、编材质。** 包名比图纸可信（`AGENTS.md` 踩坑第 8 条），
   但两个都没有的时候就是没有。
3. **中文不烤进图片。**
