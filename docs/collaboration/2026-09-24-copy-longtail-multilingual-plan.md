# 方案：文案提质 · 长尾词点击率 · 六语种全栈上架（2026-09-24）

> 甲方 09-24：「法德先做，然后日韩，然后土俄，全量上架全栈。但是你先思考方案。检查现在英西葡所有语言的
> 流畅度，拒绝机翻，行文流畅，不要生硬解释，要有格调……去看看 FSB 和 ASSA ABLOY 怎么写每个栏目……
> 长尾词那个优化别忘记，让大家不仅要搜，更要点进来。」
> 另附此前的 GEO 结论：ChatGPT 把瑞士买家送到 LC04 85×60、把澳大利亚买家送进合页目录并产生询盘，
> 靠的是「数字写成文字、型号清楚」。

## 零、结论先行

1. **先修源头，再翻译。** 英文是六个新语种的源文本。现在产品层的英文和西葡有成批的硬伤（见第一节数字），
   直接翻，等于把同一批毛病复制六遍。所以顺序是：第一阶段修产品层文案和生成器，第二阶段才开法德。
2. **我们的文风既不是 FSB 也不是 ASSA ABLOY。** FSB 卖设计师名字，ASSA ABLOY 卖集团背书，这两样我们都没有。
   要学的是它们的**结构**（每个栏目一句有立场的标题、产品页前两句交代「给谁 + 凭什么」、规格按字段列），
   声音定为「**一位把数字说清楚的工厂工程师**」：短句、数字写成文字、缺什么就直说缺什么。
3. **长尾词的目标是点击，不只是排名。** 标题把买家真正会搜的数字放在最前面，比如 LC04 的标题应含
   「85mm 中心距 + 60mm backset」，现在只有后一个。描述写成 150 字以内的完整句子，不再截断在半个单词上。
   这一条同时服务 Google 的点击率和 ChatGPT 的引用。
4. **六语种不机翻，而是按语种重写**：先建术语表，产品规格走术语表，文章按语种重新写，不逐句对译。
   法德每种语言约 1.5 到 2 周（做好的前提下）；日韩土俄需要母语审校，这是唯一需要花钱的环节。
5. **需要你给的**：Search Console 三个月的「页面 + 查询」导出、工厂的几项数据（见第六节）、母语审校预算、
   两处工程决定（路由重构、发布方式）。

## 二、向 FSB 和 ASSA ABLOY 学什么，不学什么

### FSB（fsb.de）

- **每个栏目一句有立场的标题**：「Timeless Quality」「The Story of Grip」「Greifen und Griffe」。
  标题不描述栏目，而是给出一个判断。
- **材质一句话讲完**：「Aluminum: Lightweight, durable and infinitely recyclable」
  「Bronze: Naturally patinating and antimicrobial」。三个形容词，零解释。
- **项目用一个约束来讲**：新国家美术馆翻新那页，全篇围绕一句要求「leave no visible trace」展开。
- **搜索描述短、以对方受益开头**：「Direct expert support for architects and planners.」
- **FAQ 是「问题 + 一句答案 + 去哪里」**，不写小论文。

### ASSA ABLOY（产品页，以 Lockwood 3579 为例）

- **前两句交代「给谁用 + 凭什么」**：「For use in high security government, institutional and commercial
  projects」，紧接着是标准和测试结论（防火 4 小时，AS 1905.1）。
- **卖点是短名词短语**：「All handing type features accessible without removing plates」，每条一个事实。
- **固定栏目顺序**：Features → Functions → Specifications → Downloads → Similar products → Contact。
- **品类页简介约 35 个词**，纯技术语言，不抒情。

### 我们学结构，不学腔调

- **不学 FSB 的设计师光环**：我们没有 Rams 和 Chipperfield，硬学会显得空。
- **不学 ASSA ABLOY 的集团套话**：「solutions that help secure people, places, spaces and things」这种句子谁都能写。
- **学的是**：一句有判断的标题、前两句交代给谁和凭什么、卖点一条一个事实、规格按字段列、搜索描述以受益开头。

### 我们的声音：「一位把数字说清楚的工厂工程师」

十条写作规则（新旧文案都按此改，也作为六个新语种的写作说明）：

1. 标题给判断，不给栏目名。
2. 产品页第一句 = 它是什么 + 给什么门；第二句 = 凭什么（一个数字、一项测试或一个取舍）。
3. 数字写成文字并带单位，公制在前、英制括号在后。
4. 一条卖点只写一个事实；没有数据支撑的形容词删掉。
5. 缺的数据直说缺，并说怎么拿到（「按图纸确认」），不写「如需了解请联系」。
6. 句子平均不超过 20 个词；解释性从句最多一层。
7. 不写「高品质」「专业」「一站式」这类空词；写 20 万次、304 不锈钢、4 小时。
8. 搜索描述：一到两个完整句子，150 字符以内，不截断、不以小写开头，最后半句写下一步（样品、图纸或报价）。
9. 西葡日韩等语种按本语种的行文重写，不保留英文句式；术语以术语表为准。
10. 同一族产品的通用卖点，只能写这一族**每个型号都成立**的事实（SSH018 的教训）。

Backset and centre distance decide whether a replacement drops into the existing prepara… | Mortise lock case with an 85mm centre distance and 60mm backset, euro cylinder, four round bolts, for timber doors. ## 三、长尾词与点击率

### 3.1 机制：搜索排名、点击和 AI 引用是三件事

- **AI 引用（ChatGPT、Perplexity）**：挑能直接回答带参数问题的页面，数字要写成文字、型号要清楚。
  OpenAI 抓取量与带来流量约 4:1，说明它一直在读我们的站。ChatGPT 依赖 Bing 索引，所以**每次发布后都要跑
  IndexNow**（`scripts/indexnow-submit.mjs`），让新页面尽快进入 Bing。
- **Google 点击率**：取决于标题前 50 到 60 个字符和描述是否一眼对上问题。截断的描述和小写开头都在拉低点击率。
- **排名**：长尾词竞争小，页面只要把参数写全，通常就能排上去；难点在让人点进来。

### 3.2 标题公式（按品类，把买家输入的数字放最前）

| 品类 | 公式 | 例子 |
|---|---|---|
| 插芯锁体 | 型号 + Mortise Lock Case + 中心距 + backset + 锁芯型 | LC04 Mortise Lock Case, 85mm Centre, 60mm Backset, Euro Cylinder |
| 合页 | 型号 + 材质 + 类型 + 尺寸 + 轴承 | SSH018 Stainless Steel Butt Hinge, 102×72.5×2.5mm, Ball Bearing Options |
| 推杠 | 型号 + 单/双门 + 长度 + 锁闭方式 | 316-D Double Door Panic Bar, Top and Bottom Latching |
| 筒式/圆柱锁 | 型号 + 功能 + backset + 门厚 | 5831 SSET Entrance Lock, 60–90mm Backset, 35–50mm Doors |
| 欧标锁芯 | 长度 + 分段 + 功能 + 材质 | 70mm Euro Cylinder 35/35, Double Key, Solid Brass |

标题由生成器（`scripts/build-product-titles.mjs`）统一产出，改的是公式和数据，不是逐条手写。
**长度预算**：英文 60 个字符内放下型号和两个最关键的数字；站名放最后，可被截掉。

### 3.3 描述公式

完整句子，150 字符以内：「它是什么 + 两个关键数字 + 适用门」+「下一步（图纸、样品或报价）」。
不再用「前 N 个字符 + …」的截断法。生成器改成在句子边界上取舍，放不下就少放一个从句。

### 3.4 用数据决定先改哪一页（每周循环）

1. **Search Console**：导出近三个月「页面 + 查询」。优先改**展示多（≥100）而点击率低（<1%）**的页面：
   说明已经排上去了，只差标题和描述没对上问题。
2. **Clarity**：按来源 `chatgpt.com` 筛选，被 AI 引流的产品页优先补规格。已知是 LC04 和 SSH018：
   LC04 缺面板尺寸和锁体尺寸，SSH018 缺实拍图和多角度照片，这些都要工厂提供。
3. **横评继续当总表**：锁体横评、推杠横评、筒式锁横评都直接链到具体型号，AI 先引用总表，再由总表把人
   导到具体产品。下一批：合页横评（尺寸、材质、轴承）、欧标锁芯横评。
4. **7 个采购问题**（产能、公差、备件年限等）：工厂数字一到，每条写成一页问答，AI 会原样引用。

### 3.5 回复澳大利亚合页询盘之前

17 款球轴承合页的材质还写着「Pure Copper（待确认）」。回复前先请工厂确认材质，否则报价单和网站会对不上。

## 四、六语种全栈方案

### 4.1 顺序与前提

**法语、德语 → 日语、韩语 → 土耳其语、俄语**（甲方 09-24 定）。
前提是第一阶段先把英文产品层修好（第五节），因为翻译以英文为源。

### 4.2 生产方式：按语种重写，不做机翻

| 层 | 做法 | 质量关 |
|---|---|---|
| 界面文案（十几个字典） | 逐条写，按该语种网站惯例（德语用 Sie，法语用 vous） | 编译器强制每个键都有该语种 |
| 术语表（每语种约 2,800 条） | 以西葡术语表为骨架，按该国行业标准用词：德语 Einsteckschloss（插芯锁）、Dornmaß（backset）、Entfernung（中心距）；法语 serrure à larder、axe（backset）、entraxe（中心距）；日语 箱錠、バックセット | 缺词留英文并计数，不猜 |
| 产品层（590 个） | 规格走术语表；摘要、标题、描述按第三节公式在该语种里组句 | 与英文同一套检查：无截断、无小写开头、无破折号、无英文残留 |
| 文章层（43 篇指南 + 35 篇新闻） | 按该语种重写，保留数字和结构，句式本地化 | 与西葡一样逐段对齐，每篇字数不低于英文的 90% |
| 地区用语 | 每个语种一份像 `regional-terms` 的守卫（比如法语不用魁北克词、葡语不用葡萄牙词） | 守卫测试 |

**日韩土俄需要母语审校**：这四种语言我能写到流畅、术语正确，但行业里的惯用说法需要一位母语审校
逐页过一遍，建议每种语言请一位兼职审校（按页或按字计费）。法德我可以做到直接上线的水准，
有预算的话也建议各请一位审校抽查。

### 4.3 工程

- **`Locale` 类型扩展**：一扩，十几个文案字典会全部编译报错，这是有意为之，逼每个键都补上。
- **路由**：每个语种一套约 26 个很薄的包装文件，成本不高。建议顺手重构成一个 `[locale]` 段，
  避免一个语种复制一整套路由树。
- **SEO**：九种语言互相声明 hreflang；sitemap 按语种分；llms.txt 增加各语种入口；
  **搜索索引按语种分**（现在 /es /pt 共用英文索引，09-24 只是临时加了西葡词）。
- **发布方式要先解决**：`out/` 现在 1.9GB 并提交进 git，仓库打包已 4GB。九种语言后每次发布会成倍增长，
  C 盘满就是前兆。建议六语种上线前改成「构建产物不进 git、直接同步到服务器」，需要改服务器部署脚本，要你配合。

### 4.4 工作量（做好的前提下）

| 语种 | 界面 + 术语表 | 产品层 | 文章层（约 12 万词） | 合计 |
|---|---|---|---|---|
| 法语 | 2 天 | 2 天 | 6–7 天 | 约 2 周 |
| 德语 | 2 天 | 2 天 | 6–7 天 | 约 2 周 |
| 日、韩、土、俄 | 各 2–3 天 | 各 2–3 天 | 各 7–8 天 + 审校往返 | 各约 2–2.5 周 |

法德可以并行一部分（术语表和界面可以一起做），两种语言合计约 3 周。

## 七、与 09-22 长尾词纪律的合并规则（2026-09-24 补）

> 甲方 09-24：「我们之前谈的长尾词和现在新写的 md 应该怎么结合」。
> 09-22 的口径：标题模板一定要加长尾词；为了点击率可以合理生成、组合措辞；要有场景词；以数据为准；
> 「必须做好，所有产品都优化好」。本方案的口径：工程师口吻、参数前置、描述是完整句子、同族卖点每个型号都要成立。

**两者不冲突，分的是「哪一部分可以写，哪一部分只能查」。**

### 7.1 可以组合的，和只能来自数据的

| 标题 / 描述里的成分 | 可以组合、改写（09-22「合理生成」） | 只能来自产品记录或工厂 |
|---|---|---|
| 场景词：Fire Exit Doors、Double Doors、Glass Doors、Commercial | ✔ 前提是**这个型号**装得上这种门 | |
| 品类名：Panic Bar / Panic Exit Device、Butt Hinge、Lock Case | ✔ 用买家搜的叫法，不用我们内部叫法 | |
| 供应商限定词：Factory、OEM、Wholesale | ✔ 每个产品最多一个，放在描述里优先于标题 | |
| 句式、用途、下一步（图纸、样品、报价） | ✔ | |
| 型号、尺寸、材质、轴承数、功能、锁芯型 | ✘ | ✔ |
| 认证、防火等级、ANSI / UL / EN | ✘ 永远不写，除非有证书 | ✔ 只有证书在手才写 |

一句话：**措辞可以为点击率写，数字和资质只能照抄**。合理生成用在「说法」上，不用在「事实」上。

### 7.2 标题顺序由查询数据决定，每个品类不一样

跑 `node scripts/build-query-corpus.mjs "<导出目录>"`，报告末尾「按品类」那张表就是依据
（`docs/research/QUERY-CORPUS-2026-09-22.md`）。09-22 的数据：

| 品类 | 查询数 | 数字型 | 场景型 | 泛称 | 标题公式 |
|---|---|---|---|---|---|
| 插芯锁体 | 14 | 57% | 4% | 39% | 型号 + 品类名 + **中心距 + backset** + 锁芯型 |
| 外装锁 / 夜锁 | 10 | 48% | 0% | 52% | 型号 + 品类名 + **backset / 材质** |
| 把手 / 执手 | 9 | 46% | 15% | 38% | 型号 + 品类名 + **玫瑰座尺寸 / 材质** + 门型 |
| 推杠 / 逃生 | 32 | 10% | 25% | 65% | 型号 + 品类名 + **单/双门、防火门场景** + 锁闭方式 |

三条读法：

1. **泛称占多数**：最重要的长尾词是**买家用语的品类名**本身。标题里必须有，而且每种语言用那个语言买家的叫法
   （英 panic bar / panic exit device，西 barra antipánico，葡 barra antipânico），从各语言的查询数据取，不从英文直译。
2. **型号搜索占全部查询的 20%**（fb005、bh28、564mb）：型号永远在标题最前面。
3. **样本小于 5 条的品类**默认数字优先；每次新导出重跑一遍，表会自己变。

### 7.3 长度和完整性（两份方案都认的硬规则）

- 标题：型号 + 最关键的长尾词必须落在前 60 个字符里；`| Canton Hyland` 放最后，被截掉也无妨。
- 描述：完整句子，≤150 字符，以下一步收尾；不用「…」截断，句号后不小写。
- **同族卖点必须对族里每一个型号都成立**，否则用单个产品的 `positioning` 覆盖（SSH018「球轴承」那一类矛盾就是族级卖点套到了不带轴承的型号上）。

### 7.4 「所有产品都优化好」怎么验收

生成器覆盖全部已发布产品，`titles:check` 加四条断言，任何一条不过，发布就停：

1. 标题含型号；
2. 标题含该品类在对应语言里的买家用语品类名；
3. 前 60 个字符内含至少一个长尾成分（按 7.2 的公式：数字或场景）；
4. 标题和描述里不出现认证、防火等级、标准号（有证书的型号走白名单）。
