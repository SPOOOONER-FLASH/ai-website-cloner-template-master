## 二、改了再搬（adapt）：从强到弱共 7 条

### 2. 产品页"报价需要您提供"块
- **是什么**：产品记录缺尺寸或规格时，页面既不留白也不编数字，而是显示一块设计过的区域：按品类列出报价必须的信息（例如门厚、中心距、左右开向、表面处理、数量），再放一个预填好型号的询盘链接。
- **为什么**：把"缺数据"变成"工厂有固定流程"。缺口很多：卡片规格行 276/636 个产品没有，尺寸图只有 42/435 个产品有。这也符合"缺就写横线、问清楚、不替老板填"的规矩。
- **怎么做**：在 `ProductDetail.tsx` 加一个区块。各品类要列的输入项由 Claude 放进 `src/lib` 或 `src/data`。样式只用现有 token（`surface-alt` 加 1px 细线），不用远高的蓝色虚线框或奶油底色。**和远高相比的改动**：不搬 sticky 章节标签（`ProductDetail.tsx` 有 900 多行，改动太大，留到阶段 3 再说），也不搬视差安装大图和首字下沉。
- **谁做**：Claude 写数据和三语文案，Codex 做样式。
- **工作量**：6–10 小时。
- **风险**：这会改到转化路径，按规矩要先用 `cro` 技能。每个品类的输入清单必须来自真实的报价流程，拿不准的项列出来请老板确认。
- **分歧**：买家信心和性能两个角度想同时加 sticky 标签，代码角度认为改动太大。定为先做这个区块。

### 3. 文档化编号：产品页型号条 + 图片 FIG 编号
- **是什么**：产品页顶部加一条上下两根 1px 墨线夹住的小字条，左边写"型号 · 品类"，右边写"本品类共 N 款"。图库每张图在 HTML 里标 `FIG 01 / 03`（不烧进图片里）。文章表格的标题可以加 `Table 01 ·`。
- **为什么**：完全不用动效，就能让页面像一份受控文件，也就是"一致性本身就是论据"。
- **怎么做**：改 `ProductDetail.tsx` 和 `ProductImageZoom.tsx` 的图库。字号用现有的 c2/kicker（不小于 13px，这是 `type-scale.test.ts` 的下限），数字用 tabular-nums，"共 N 款"在构建时从 `content/products` 算出来。**和远高相比的改动**：不写"Technical datasheet"，因为 `ProductDetail.tsx` L97 写明规格书"按需提供，资料库准备中"；不用"第 n / N 个"这种序号，加一个产品就全部变动；编号不贴在型号旁边，309-D、AR4 才是客户下单认的身份。
- **谁做**：Codex 做样式，Claude 写三语文案。
- **工作量**：4–6 小时。
- **风险**：`product-image-zoom.test.ts` 里"只有一个缩放组件、不出现放大镜图标"的断言必须保持通过。
- **分歧**：买家信心角度想要"nn / NN"位置序号，代码角度指出它不稳定；以代码角度为准。

### 4. 规格数字排版（等宽对齐数字）
- **是什么**：所有尺寸、规格值统一用等宽对齐数字（tabular-nums）。订货代码改用系统等宽字体 `var(--font-mono)`，这个变量在 `globals.css` L1601 已经有了。再加一个不小于 13px、字距放宽的眉标样式。远高那种"同一字体家族里宽体眉标配窄体大数字"的效果，要先测过 Archivo 可变宽度字体文件的体积再决定。
- **为什么**：数字看起来像量出来的，而不是写出来的，而 HYDE 卖的就是尺寸。在远高的"精致感"里，这一块最便宜，也最不像装饰。
- **怎么做**：在 `globals.css` 加一个 `.numeral` 工具类。**和远高相比的改动**：不加 JetBrains Mono、IBM Plex Mono、Noto Sans SC（d1 的导出因中文字体切片涨到约 33 MB），不用 800–900 字重。在 ar/ja/ko/zh 下取消大写和字距。h1 到 c2 的字号仍受 `type-scale.test.ts` 约束。
- **谁做**：Codex。
- **工作量**：4–8 小时，含字体体积测量。
- **风险**：如果可变字体比现在的静态 400/600/700 三个字重大，或者会引起版面跳动（CLS），就不换。字体必须继续自托管（`src/app/fonts.ts`），用 Google Fonts 链接在大陆会白屏。
- **分歧**：买家信心角度想直接上宽度轴，另外两个角度要先测量；定为先测。

### 5. 统一的章节开头（SectionHead）
- **是什么**：一个组件包含眉标（现有 `.text-kicker`）、`.text-h2` 和可选导语，章节之间用 1px 细线隔开。确实有先后顺序的地方可以写"Step 01 · …"。
- **为什么**：09-28 评审发现章节标题有三种规格并存：AR4 是 32/700，其他是 28/600，模块标题是 20/600（见 `docs/collaboration/tasks/2026-09-28-hyde-visual-bau-options.md` 第 3 项）。统一以后整站像一个系统，"大气"首先来自这里。
- **怎么做**：只用现有的 class，不加新字号，所以 `type-scale.test.ts` 不用动。顺带把 AR4 的 32/700 改回统一规格。**和远高相比的改动**：不加 DrawRule 画线动画，不默认深浅章节交替，不用超大中文宣言。改动涉及很多文件，动手前先在 `NOW.md` 加一行认领。
- **谁做**：Codex，先出提案，客户选定再做。
- **工作量**：8–12 小时。
- **风险**：会碰到很多页面文件，容易和尚未定下的导航方案打架。`home-accent.test.ts` 锁定的模块数量不能变。

### 6. 页面比例测量：让"大气"能量化
- **是什么**：一个脚本，量出每个页面各章节的高度和总高，和 FSB 的参考截图对比。
- **为什么**：远高自己已经证明，动画加得越多，页面就越长。HYDE 首页约 16.2k px，FSB 约 10.9k px。大气靠的是留白和比例，不靠特效；不去量，就只能凭感觉判断。
- **怎么做**：在 `scripts/audit-hyde-desktop-rhythm.mjs` 上扩展。它已经用 Chrome DevTools 协议测 390、1440、1920 三个宽度，也已经查横向溢出。结果写到 `tmp/`，用已经装好的 `sharp`，不新增依赖。先当作测量工具，不当作 CI 门槛。**和远高相比的改动**：不搬 SSIM 线框相似度评分，也不搬 PhotoSlot 克隆流程。
- **谁做**：Claude（`scripts/`）。
- **工作量**：4–6 小时。
- **风险**：低。FSB 只用来对照比例，不照抄它的版式和素材（`PRODUCT.md`）。

### 7. 可复制的五金规格行
- **是什么**：产品页上给写规格书的人一段可以直接粘贴的五金规格行，包括型号、功能、中心距、门厚范围和表面代码，项目相关的值留 `____`。旁边一个复制按钮。
- **为什么**：建筑师（BAU 2027 的主要访客）拿到就能用。能直接给出规格行的供应商，显得懂自己的产品。
- **怎么做**：在 `src/lib` 里只用产品记录中已有的字段生成，并配单元测试；字段不全就不显示。规格行以可见 HTML 输出，搜索引擎能抓到。复制按钮是一个很小的客户端组件，复制后用 `aria-live` 提示"已复制"。**和远高相比的改动**：只有当 `src/data/company` 里的证书记录覆盖到这个具体型号时，才写标准或等级；HYDE 没有 ANSI/BHMA 等级。
- **谁做**：Claude 负责生成逻辑和文案，Codex 负责按钮样式。
- **工作量**：6–8 小时。
- **风险**：最大的风险是暗示了没有认证的等级。错一个等级，买家会连带怀疑其他所有内容。第一版只做 BAU 访客会写进规格的品类。

### 8. 唯一一处入场动效：开篇标题从遮罩下升起
- **是什么**：每页开篇的大标题（`.text-d1`，每页只有一个）在加载时从一条遮罩下面平移升起，只播一次，时长 560 ms（`--motion-slow`）。用的缓动曲线 `cubic-bezier(0.22,1,0.36,1)` 和 d4 完全相同，HYDE 的 `--motion-ease` 本来就是这一条。
- **为什么**：这是对老板"动效、精致"这个要求最直接的回应：只有位移，没有模糊也没有淡入，像印刷品翻页。`DESIGN.md` 本来就把 560 ms 留给"一处专门设计的揭示动效"。
- **怎么做**：纯 CSS `@keyframes`，页面加载时播放。不用 IntersectionObserver，不装动画库。CSS 动画不运行时，标题直接停在原位；开启"减少动效"时是 `animation:none`。保留 `pb-[0.08em]`，免得字母下伸部分被裁掉；最多两行、一次错位。**和远高相比的改动**：时长从 1.1 s 压到 560 ms；不搬淡入上浮的 Reveal、WordReveal 和 DrawRule；不用在首页 HeroCarousel 的 h1 上（`static-export-performance.test.ts` 锁定首帧只有一张）；同一页不再有其他动效。
- **谁做**：Codex 出提案页，客户选定后实施，再跑一次 Impeccable 检测和 `motion:check`。
- **工作量**：3–5 小时，另加提案时间。
- **风险和分歧**：性能角度指出，标题被遮住期间 LCP（最大内容绘制时间）会推迟，主张只用在首屏以下的 h2 上；另外两个角度反对用观察器触发，因为 SiteFacts 出过内容卡在透明度 0 的事故。定为只用在开篇标题不是 LCP 元素的页面，上线前用 web-perf 实测；不做滚动触发。客户 09-07 否过推拉镜头动效，10-04 否过三套动感首页方案，所以必须先给他看，不能直接上线。

**另有 10 条较弱的"改了能搬"没进前 8**：询盘表单旁的纯文本预览（会改转化路径、表单变高）、照片统一调色（只能在 KANEE 照片流程里从源头做，不能用 CSS 叠层）、安装步骤 sticky 图解（等工厂提供带尺寸的安装图）、尺寸线逐笔画出的动效（`ProductDrawing.tsx` L23 写明故意用 `<img>` 而不是内联 SVG，画不了线）、大菜单产品缩略图（并入 10-04 的四个导航方案）、fillRows 照片网格补齐、指南文章的编号小标题、陈述式短标题、"弱图只小图展示"写入 DESIGN.md、横向轨道的箭头按钮。
