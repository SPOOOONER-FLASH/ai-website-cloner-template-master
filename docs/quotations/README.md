# 报价单 —— 先读这一页

生成：`py scripts/build-quotation.py docs/quotations/<job>.json`
A4 校验：`powershell -File scripts/verify-quotation-a4.ps1 "<xlsx>"`
卖方抬头只在 `_company.json`，与 `content/site-settings.json` 同步修改。

## 两条硬规矩（甲方 2026-09-23 定）

### 1. 不清楚就问，问到精确为止

甲方或老板的表述短、带口语，**有两种读法时不要选一种先做**，先问，问到只剩一种读法。
问题要具体，把候选列出来让对方选，例如：「10.44 是 A 推杆还是 B 拉手？」

**客户发来的照片不一定都是要报价的产品。**很多是参考图，意思是「我要这种」。
报价的行数，以老板给出的价格条数为准，不以照片张数为准。

### 2. 不知道的信息一律不填，等老板安排

付款方式、交期、数量、包装、MOQ 等，老板没给的，单元格写 `TBC` 或留空，
交稿时附一张清单：「以下几项需要老板确认」。

**不要从旧报价单、仓库里的通用说法或常识里找一个数填上。**
填上的数看起来像确认过的条款，读者会照着执行；留空反而安全。

## 为什么有这两条：REFCON 一单（2026-09-21）

| 我做的 | 老板改的 | 错因 |
|---|---|---|
| 三行 330 / 302 / 039 | 两行 330 / 039 | 客户的银色推杆照片是参考图，我编出了一行 302 |
| 10.44 给 302，拉手不报价 | 10.44 是拉手 | 「是拉手没报价给我改一下」读反了，也没追问 |
| 付款 100% T/T、交期 30 天 | 30/70、50 天 | 老板没给，我从旧模板填的（规矩 2） |
| 备注推销 317 | 删掉 | 没人要的内容不加 |

当时已经出现一个信号：不锈钢 302 比铁制 330 便宜 45%。**价格和产品对不上常理，
就说明对应关系错了**，要停下来问，不要照样交稿。
